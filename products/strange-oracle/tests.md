# 계산 테스트 — strange-oracle

계산 코드: `astro.js`. 재작업·확인일: 2026-09-25 (1-A 천체 계산 정밀도 재작업). 모든 케이스를 Node v20.16.0으로 실제 실행해 확인함.
(이전 기록 2026-09-24는 직접 구현한 Meeus 축약식 기준이었고, T1이 0.014° 차이로 교과서 자릿수 일치에 미달해 교체함.)

## 계산 방식
| 항목 | 방식 |
|---|---|
| 달 위치 | Astronomy Engine 2.1.19 `EclipticGeoMoon` — 지구 중심, 참 황도·참 춘분점(세차+장동) 기준 황경 |
| 태양 위치 | Astronomy Engine 2.1.19 `SunPosition` — 지구 중심, 참 황도·참 춘분점 기준 겉보기 황경(광행차 포함) |
| 장동 Δψ | Astronomy Engine `e_tilt` (IAU 2000B) |
| UTC→TT (ΔT) | Astronomy Engine 내장 ΔT 모델 |
| 라히리 아야남샤 | 직접 계산(아래). 근사식이 아니라 정의값 + 세차 공식 |
| 나크샤트라·라시 | 항성 황경 = 열대 황경 − 참 아야남샤. 나크샤트라 = ⌊항성 달 경도 ÷ 13.333…°⌋, 파다 = 한 칸을 4등분, 라시 = ⌊경도 ÷ 30°⌋ |

라히리 아야남샤:
- 정의점: 1956-03-21 0시 TT(JD 2435553.5)에 평균 아야남샤 23.250182778° − 0.004658035° = 23.245524743°.
  출처: Swiss Ephemeris 소스 `sweph.h`의 아야남샤 표 1번(Lahiri) 항목 `{2435553.5, 23.250182778 - 0.004658035, ...}`. 주석에 인도 역법개혁위원회(1956)·Indian Astronomical Ephemeris 1989 기준이라고 적혀 있음.
- 이후: IAU 2006 일반 세차(황경 방향) p_A = 5028.796195″t + 1.1054348″t² + 0.00007964″t³ − 0.000023857″t⁴ − 0.0000000383″t⁵ 만큼 증가 (Capitaine·Wallace·Chapront 2003, IERS Conventions 2010 식 5.40). t는 J2000부터의 율리우스 세기(TT).
- 달·태양 경도가 참 춘분점 기준이므로 장동 Δψ를 더한 참 아야남샤를 뺀다.
- Swiss Ephemeris는 이 정의점을 IAU 1976 세차로 옮기므로 방식이 조금 다르다. 차이는 A1에서 0.3″ 이내로 확인함.

## 처리 방식
사주 제품의 필수 항목(입춘·절기·자시)은 **해당 없음**: 이 제품은 사주 만세력이 아니라 달·태양의 황도 경도로 계산한다.

| 항목 | 처리 |
|---|---|
| 시간대 | 입력은 한국 시간(UTC+9)으로 보고 9시간을 빼 UTC로 바꿔 계산(`julianDayKST`, 기존과 같음). 1987~88년 한국 서머타임은 반영하지 않음 (최대 1시간, 달 약 0.5° 차이) |
| 태어난 시각 모름 | **2026-09-25 변경(1-B/1-C1, designer 요청 3번)**: 그날 한국 시간 0:00 ~ 다음 날 0:00 동안 달이 거친 나크샤트라를 **모두**(최대 3개) 찾는다(`dayCandidates`). 경계 시각은 이분법으로 1초 안까지 좁히고, 분 단위로 반올림한 시간 구간(startMin~endMin)과 하루 중 비율(share)을 넘긴다. 후보별 결과는 그 구간 한가운데 시각으로 계산. 후보 1개면 정오 값으로 결과 1개(후보 화면 없음), 2~3개면 후보 화면에서 사용자가 고름. 의식 화면 바퀴는 그날 정오의 달 위치에서 멈춤 |
| 날짜 범위 | 1900~2100년만 받음 (app.js 입력 검사, 변경 없음) |
| 정밀도 | 라이브러리 명세 ±1각분(0.0167°) 이내. 실측은 아래 표. 나크샤트라 한 칸은 13.33°라 경계 몇 초각 안에서만 영향 |
| 공개 함수 | `window.Astro = { birthChart, dayCandidates, moonLongitude, sunLongitude, ayanamsa, julianDayKST }`. birthChart 반환값에 `candidates`(후보별 chart·startMin·endMin·share)와 `noon`(의식 화면 바퀴 위치)이 추가됨. 천체 계산 함수(달·태양·아야남샤)는 바뀌지 않아 아래 교과서 대조(M1~A1, S1)는 그대로 유효 |

## 허용 오차와 근거
- 교과서 대조(M1, M2): **60″(1각분)**. 근거: Astronomy Engine README "accurate to within ±1 arcminute", "rigorously unit-tested against NOVAS, JPL Horizons" (https://github.com/cosinekitty/astronomy). 이 제품은 라이브러리를 쓰므로 CLAUDE.md 3장의 "직접 구현 시 자릿수 일치" 기준 대신 라이브러리 정확도 명세를 허용 오차로 삼는다.
- 장동(M3): 1″. 근거: 교과서(Meeus)는 IAU 1980 이론, 라이브러리는 IAU 2000B라 이론 차이만큼 다를 수 있다. 1″는 달 위치 허용 오차(60″)보다 훨씬 작아 결과에 영향이 없다.
- 아야남샤(A1): 1″. 근거: 같은 정의점에서 세차 모형(IAU 2006 vs IAU 1976)만 다르므로 1″ 미만이어야 정상.
- 전 범위 대조(S1): 과거 날짜 60″ (라이브러리 명세). 미래 날짜는 ΔT(지구 자전 지연)를 미리 알 수 없어 라이브러리마다 예측값이 다르다(M4). 이 차이는 계산 오류가 아니라 예측 불확실성이므로 따로 적는다.

## 알려진 한계
1. **미래 날짜의 ΔT**: 2026년 이후는 지구 자전 지연(ΔT)을 예측값으로 쓴다. Astronomy Engine과 Swiss Ephemeris의 예측이 2100년에 약 110초 벌어지고, 달이 이 사이 약 1′ 움직인다. 태어난 날 입력이 대부분 과거라 영향은 작다. 과거 날짜(1900~2026)는 두 라이브러리가 5″ 안에서 일치.
2. ~~시각 모를 때 가운데 집 누락~~ → 2026-09-25 해소(T4b·T4d). 이제 하루 동안 거친 집을 모두(최대 3개) 후보로 보여 준다. 시간 구간은 분 단위로 반올림하므로 30초가 안 되는 구간은 후보에서 빠진다. 그런 날이 몇 번 있는지는 세지 않았다(미확인).
3. 1987~88년 한국 서머타임 미반영 (기존과 같음).

## 테스트 실행 방법
임시 폴더에 `astronomy-engine@2.1.19`(jsdelivr 파일과 SHA-256 동일 확인)와 `sweph@2.10.3-8`을 설치하고, jsdelivr 파일과 `astro.js`를 가짜 `window`에 올려 위 케이스를 계산했다. 스크립트는 제품 폴더에 두지 않았다.

## 운영자가 추가로 확인할 것
- M2의 Meeus 책 인쇄값(199°54′21.818″)은 원문 대조를 못 해 미확인. 책이 있으면 한 번 확인해 주세요 (어느 쪽이든 허용 오차 안).
- T3를 외부 베다 점성술 계산기(라히리, 한국 시간)와 대조하는 것은 Swiss Ephemeris 직접 계산으로 대신함. 웹사이트 화면 대조는 하지 않음.
