## 디자인 방향
- **신비로운·이국적인 → "밤의 박물관"**: 운영자가 좋아하는 남보라 밤하늘 + 금빛 달 톤을 공통 바탕으로 그대로 둔다. 방에 들어서면 강조색 하나(룬=얼음 푸른빛, 별=달빛 보랏빛)와 위쪽에서 새어 드는 빛의 색만 바뀌어 "다른 전시실에 들어왔다"는 느낌을 준다. 명도는 같고 hue만 다르다 (동명도 팔레트).
- **소름 돋는(알아맞혀진) → "읽히는 글"**: 결과가 10분 이상 읽는 긴 글이므로 이번 디자인의 핵심은 가독성이다. 본문 17px·줄 간격 1.85·한 줄 약 18~26자, 읽는 동안 반짝이는 별을 낮추고, 장마다 로마 숫자 머리·첫 문단 강조·인용 한 줄·다음 장 떡밥 문장으로 리듬을 만든다. 위에 붙은 막대에 "몇 번째 장·어디까지 읽었는지"가 늘 보인다.
- **유치하지 않게·겁주지 않게**: 해골·붉은색·깜빡임 없이, 금속선·아치 문·돌·달처럼 박물관 유물에 가까운 절제된 도형만 쓴다. 의식 연출은 방마다 다르다: 룬은 **손으로 쥐고 흔들고 뒤집는 촉각**(가까이, 아래쪽, 차가운 돌), 별은 **손대지 않고 지켜보는 되감기**(멀리, 큰 숫자, 돌아가는 하늘).
- **(2차) 살아 있는 우주**: 단색 남색 대신 깊이가 있는 우주를 깐다. 천천히 흐르는 성운 2겹, 오로라 띠, 멀고 가까운 별 3겹(원근·스크롤 시차), 떠오르는 먼지, 가끔 지나가는 유성. 방에 들어가면 성운·오로라가 그 방의 빛깔로 바뀐다. 방 문은 빛이 소용돌이치는 **포털**이고, 누르면 빛에 빨려 들어가며 다음 화면이 흐림 속에서 떠오른다. 결과는 **봉인이 그려졌다 부서지며** 드러난다. 단, 긴 글을 읽는 동안에는 배경이 멈추고 어두워진다(가독성 최우선).

### UX 목표 달성 방법 (기획서 "UX 목표")
- **방 하나 60초 이내(의식 제외)**: 허브 문 → 시작(스크롤 없이 버튼) → 입력(룬: 주제 기본 선택돼 있어 버튼 한 번, 별: 날짜 3칸) → 의식. 이름·생년월일이 저장돼 있으면 입력 화면에서 "지난번 정보" 카드만 확인하고 바로 버튼. 탭 수: 허브 1 + 시작 1 + 입력 1 = 3탭.
- **의식 3~6초**: 룬은 1.8초 누르기 + 돌 3번 누르기(사용자 속도), 별은 약 5초 (JS 타이머 5.2초, CSS 회전 4.4초, 진행 막대 `--ritual-ms` 5초).
- **입력 최대 2개**: 룬 = 이름(선택)+주제, 별 = 날짜+시각(이름은 선택). 시각은 "몰라요" 체크를 반드시 제공.
- **이탈 우려 (1) 소개가 길다**: 시작 화면 소개는 2~3문단 카드 하나, 주요 버튼은 화면 아래에 붙어(sticky) 스크롤 없이 보인다.
- **이탈 우려 (2) 결과가 길다**: 목차(장 제목+예상 시간) → 장마다 머리·첫 문단·인용·떡밥 → 위 막대의 읽기 진행률. 장 끝의 떡밥 문장은 강조색 가운데 정렬로 "다음 장이 있다"는 신호를 준다. 공유 버튼은 캡처 카드 바로 아래(작은 보조 버튼)에도 있어, 끝까지 읽지 않은 사람도 공유할 수 있다.
- **이탈 우려 (3) 유료에서 뭘 주는지 모름**: 나의 이야기의 유료 안내 카드에 목차 4줄을 그대로 보여 준다 (1단계는 결제 없음, "곧 열려요").

## 화면별 명세

### 공통: 상단 막대 (모든 화면)
- 레이아웃: 왼쪽 뒤로 버튼("← 입구로" 등) / 가운데 현재 장 표시(결과 화면만, 예 "II · 사건 2/4") / 오른쪽 "내 정보 지우기". 높이 52px, 스크롤해도 위에 붙음(sticky), 반투명+흐림.
- 결과 화면에서는 막대 아래 가장자리에 4칸 읽기 진행률(장 하나 = 한 칸). 지나간 장 `.is-done`, 읽는 중인 장은 `style="--fill:0~1"`.
- 허브에서는 뒤로 버튼을 숨긴다(`.is-hidden`). "내 정보 지우기"는 허브 포함 모든 화면에 항상 보인다 (기획서 개인정보 "모든 화면 상단").
- **(2차) 캡처 문제 수정**: ① "내 정보 지우기"가 두 줄로 꺾이던 것 → 아이콘+글자 한 줄 고정(`white-space: nowrap`), 칸 배치를 `auto 1fr auto`로 바꿔 가운데 장 표시가 남는 폭만 쓰고 넘치면 말줄임. ② 허브에 "II · 사건 2/4"가 보이던 것 → 정적 검토 모드에서 억지로 보이게 하던 규칙을 지움. 장 표시·진행률은 `.topbar.is-reading`(결과 화면)일 때만 보인다. 결과 화면의 막대 모습은 룬 결과 섹션 맨 위의 검토 전용 견본(`data-preview-only`)으로 확인.
- 사용 컴포넌트: 제품 전용(.topbar, .read-progress).
- 상태: 기본 / 읽는 중(`.topbar.is-reading`).
- 인터랙션: "내 정보 지우기" → 확인 대화상자(`<dialog>` showModal) → "모두 지우기" 시 sessionStorage 삭제 → 토스트 "모두 지웠어요" → 허브로. "그대로 두기"는 닫기만.

### 0. 허브
- 레이아웃: eyebrow(WORLD ORACLE HALL) → 로고 "낯선 점술관"(금빛 그라데이션 44px) → 부제 2줄 → **열린 문 2개(2열 아치 문)** → 나의 이야기 진행 카드(방문 1개 이상일 때만) → 다음에 열리는 방 4개(점선 아치 2×2, 예고만) → 소개 글(300자 이상) → 광고 자리.
- 360×640 기준 문 2개가 스크롤 없이 보인다 **[코드 판단: 막대 52 + 머리 약 190 + 문 약 250 ≈ 490px]**, 실제 글꼴 줄바꿈은 **[화면 확인 필요]**.
- 문: 방마다 자기 강조색(룬=얼음, 별=달빛)으로 테두리·기호·위쪽 빛이 칠해진다. 아치 반지름은 컨테이너 쿼리(cqi)로 문 폭의 절반 = 360px·480px 모두 반원 아치.
- **(2차) 포털**: 문 위쪽에 지름 104px 포털 — 안쪽은 방 빛깔의 소용돌이(16초에 한 바퀴, 두 문은 서로 반대 방향), 가운데 빛샘과 바깥 테두리 빛이 3.2초 주기로 맥동(두 문은 반 박자 어긋남), 한가운데 방 기호(룬 ᚱ / 초승달). 누르면 포털이 커지며 빛으로 삼키고 글자가 사라진 뒤 방으로(아래 애니메이션 명세 A-3).
- **(2차) 글자 크기**: 캡처에서 작고 빽빽하던 문 안 글자를 키움 — 방 이름 19→22px, 출신 13→14px(강조색), 설명 14→16px, 문 최소 높이 248→290px. 설명은 최대 18자(3줄)로 줄인다(텍스트 길이 제한 참조). 허브 머리(달 문장 64px + 로고)를 줄여 360×640에서도 포털 2개가 첫 화면에 들어오게 했다 **[화면 확인 필요]**.
- **(2차) 닫힌 방**: "아직 봉인된 방" — 로마 숫자가 점선 원 안에 든 흐린 봉인 모양.
- 사용 컴포넌트: 제품 전용(.door, .story-teaser, .arch-mark, .closed-room, .about), base(.eyebrow, .ad-slot).
- 상태: 방문한 방 문 `.is-visited` → 아래에 "6장 채움" 배지. 나의 이야기 카드: 방 0개면 숨김(`.is-hidden`). 닫힌 방은 누를 수 없음(버튼 아님).
- 인터랙션: 문 누름 → 해당 방 시작 화면. 문에 hover/focus 시 2px 떠오름+빛. 화면 전환은 공통 `screen-in` 0.7초(아래에서 12px 떠오르며 나타남).

### 1. 방 시작 (룬 / 별 공통 틀)
- 레이아웃: 방 상징(룬=돌 모양 안의 ᚱ, 별=점선 궤도 안의 초승달) → eyebrow → 방 이름 → "나의 이야기 6장 · 과거·현재·미래" 알약 → 셀링 한 줄 → 문화 소개 카드(2~3문단) → **아래에 붙은 주요 버튼**.
- 사용 컴포넌트: 제품 전용(.room-head, .room-emblem, .lore, .cta-dock), base(.btn--primary).
- 상태: 기본만.
- 인터랙션: 버튼 → 입력 화면. 뒤로 → 허브.

### 2. 방 입력
- 룬: 제목 "무엇을 물어볼까요?" → [저장된 정보 카드] → 이름(선택, 최대 10자) → 주제 칩 4개(2×2, 첫 칩 기본 선택, 한 번에 하나) → 개인정보 안내 → 주요 버튼.
- 별: 제목 "언제 태어났나요?" → [저장된 정보 카드] → 이름(선택) → 태어난 날 3칸(년 4자리/월/일, `inputmode="numeric"`) → 태어난 시각 2칸(시 0~23/분) + "태어난 시각을 몰라요" 체크 + 안내 한 줄 → 개인정보 안내 → 주요 버튼.
- 날짜를 `type="date"` 대신 숫자 3칸으로 바꾼 이유: designer.md 원칙(날짜는 numeric), 모바일 달력 선택기에서 30년 전으로 넘기는 수고 제거.
- 저장된 정보 카드: "지난번에 알려 준 정보 / 김서윤 · 1995. 3. 21. · 시각 모름 / 이 정보로 이어서 볼까요? / 다시 입력하기". 카드가 보이면 같은 항목의 입력칸은 숨긴다(`.is-hidden`). "다시 입력하기" → 카드 숨기고 입력칸을 값이 채워진 채로 보여 줌. 주요 버튼은 하나 그대로(카드 상태에서도 같은 버튼으로 진행).
- 개인정보 안내: 입력칸 바로 아래, 자물쇠 아이콘 + "이 기기의 이 탭에만 잠시 보관되며 어디에도 전송되지 않아요 …". 처음 저장하는 시점(저장된 정보가 없을 때)에 반드시 보이고, 저장된 정보 카드가 보이는 상태에서는 숨겨도 된다.
- 사용 컴포넌트: base(.field, .input, .input--num, .chip-group, .chip, .check, .notice, .field__error), 제품 전용(.saved-info).
- 상태: 기본 / 저장된 정보 있음 / 오류(`.field.is-error` + `.field__error` 보임) / 시각 모름(시·분 칸에 `disabled`, 흐리게) / 비활성 없음(버튼은 누르면 검사하고 오류를 보여 준다).
- 오류 문구는 고칠 방법을 담는다: "날짜를 확인해 주세요. 1900년에서 2100년 사이로 넣어 주세요 (예: 1995년 3월 21일)", "태어난 시각을 넣거나 '몰라요'를 체크해 주세요".
- 인터랙션: 칩 누름 → 즉시 선택 전환(0.15초 색 전환). 입력칸 포커스 → 강조색 테두리+3px 번짐. 버튼 → 검사 통과 시 의식 화면.

### 3-R. 룬의 방 의식 (주머니 흔들기 → 돌 뒤집기)
- 레이아웃(한 자리에서 바뀜): 안내 문구 2줄 → [주머니 단계] 가죽 주머니 176px + 둘레의 룬 24자 고리(반지름 124px) → [돌 단계] 얼음판(타원) 위 돌 3개(가운데 돌이 조금 높음) → 노른 안내 한 줄.
- 주머니 단계: 누르고 있는 동안 둘레의 룬 24자가 ᚠ부터 하나씩 켜진다. JS는 `ol[data-js="rune-ring"]`의 `--progress`(0~1)만 바꾸면 되고, 글자별 밝기는 CSS가 계산한다. 손을 떼면 progress가 줄어 글자가 다시 꺼진다(기존 동작). 흔들림 `.is-shaking`, 다 차면 `.is-spilled`(0.6초 기울며 사라짐).
- 돌 단계: 주머니 영역에 `.is-hidden`, 얼음판에서 `.is-hidden`을 떼고 `.is-cast`를 붙이면 돌이 0.15초 간격으로 떨어진다. 다음에 뒤집을 돌 `.is-next`(얼음빛 테두리가 1.6초 주기로 숨쉼). 누르면 `.is-flipped` → 0.9초 회전하며 룬이 나타나고 서리 고리가 번진다. 세 번째를 뒤집고 1.6초 뒤 결과로.
- 별의 방과 다른 점: 손을 계속 대고 있어야 하는 능동 연출, 차가운 돌·얼음판·가죽 질감, 화면 아래쪽에 무게, 소리 대신 진동(기존 `navigator.vibrate`).
- **(2차) 주머니 다시 그림**: 캡처에서 "갈색 항아리"로 보이던 것을 **한밤 남색 가죽 룬 주머니**로 — 벌어진 입구 주름 → 졸라맨 목 → 은 매듭끈과 늘어진 술 2가닥(3초 주기로 흔들림) → 은실 바느질선이 있는 불룩한 몸통 → 몸통 가운데 **룬 인장**(원형 메달 안에 ᛟ 오탈라). 대기 중 4초 주기로 살짝 떠 있고, 발밑에 얼음빛 기운이 숨쉰다.
- **(2차) 누를수록**: `--progress` 하나로 ① 룬 24자가 ᚠ부터 켜지며 밝아지고 커지고 빛남, ② 고리를 따라 서리 띠가 원을 그리며 차오름, ③ 인장의 룬이 하얗게 달아오르고 빛이 번짐, ④ 기운이 커진다. 다 차면 룬 24자가 바깥으로 흩어지며 사라지고 주머니가 기울어 쏟는다.
- **(2차) 돌 뒤집기**: 돌 뒷면의 룬은 이제 글꼴 문자가 아니라 **SVG 획**(index.html 맨 위 룬 24자 획 모음)이다. 뒤집히면 1초 동안 끌로 새기듯 획이 그려지고, 다 새겨지면 한 번 번쩍인다. 얼음판에 돌이 떨어질 때 서리 결이 퍼진다.
- 움직임 줄이기: 흔들기 대신 주머니가 밝아짐, 돌은 떨어지지 않고 제자리, 뒤집기는 즉시 전환. 누르는 시간(1.8초)은 JS가 짧게(예: 0.6초) 줄이는 것을 권장(developer 요청).

  8. **주요 버튼: 결과 카드 저장·공유** + 보조: 다시 던지기 / 다른 날짜로 보기
  9. 이 방에서 얻은 원형 한 줄 근거
  10. 다음 방이 궁금하다면: 떡밥 카드(1단계 1장, 이후 2장. 도착할 방의 색으로 칠해짐) + "나의 이야기 보기 · n/6장"

### 5. 나의 이야기 (1-C2 신규)
- 레이아웃: eyebrow MY STORY → "김서윤님의 이야기" → 부제 → **아치 6개 진행 표시 + "1 / 6장"** → **원형 카드(캡처 영역)**: 8방향 별 문장(紋章), "지금까지 나의 원형은", 원형 이름(44px), 상태 문장("지금까지는 OO 원형이에요. 아직 X개 방이 남아 있어요"), 설명, 근거 목록(방·결과·원형 태그) → 작은 보조 공유 버튼 → **이야기의 등뼈(1~6장 고정 순서, 세로 실로 이어짐)** → 유료 안내 카드 → 주요 공유 버튼 → 끝 장식 → 광고 자리.
- 장 상태 3가지:
  - `.is-done`(방문): 노드가 방 색으로 채워짐, 결과 유형 이름, 요약(300~500자), "전체 다시 보기 →"
  - `.is-available`(방은 열렸는데 아직 안 감): 점선 노드, "아직 열리지 않음 — 별의 방에서 열 수 있어요" + "별의 방에서 열기 →" 버튼
  - `.is-upcoming`(방이 아직 안 열림): 흐린 노드, "아직 열리지 않음 — 다음에 열려요", 버튼 없음
- 방 1개만 방문해도 "1장짜리 이야기"로 완결되어 보이게: 원형 카드가 꽉 차 있고, 나머지 장은 빈칸이 아니라 예고 문장으로 이어진다.
- 방 0개(나의 이야기에 바로 들어온 경우): 원형 카드 `.is-empty`(문장 흐리게, 이름 대신 "?" 등) + "아직 첫 장이 비어 있어요" 블록(방 2개 버튼). 공유 버튼은 숨김.
- 6개 모두: 원형 카드 `.is-complete`(상태 문장이 강조색, "완성된 원형"). 1단계에서는 도달 불가.
- **(2차) 별자리처럼 그려지는 문장**: 들어오면 약 3초 — 테두리 원이 그려지고 → 8원형을 뜻하는 점 8개가 차례로 톡 켜지고 → 점들을 잇는 선(팔각형과 대각선)이 그려지고 → 8방향 별이 그려진 뒤 채워지고 → 가운데 점이 점등 → "지금까지 나의 원형은" → 원형 이름이 떠오름 → 상태·설명.
- **(2차) 불이 켜지는 장**: 위 아치 6개 중 채워진 장이 차례로 번쩍이며 점등(0.12초 간격). 아래 등뼈는 실이 위에서 아래로 자라고, 완료한 장의 원 노드가 보일 때 번쩍이며 불이 켜진다. "열 수 있음" 장의 점선 노드는 포털처럼 은은히 맥동.
- 유료 안내 카드(1단계): 목차 4줄 + "3,900원 · 곧 열려요"(2차 확정) + 비활성 버튼 "곧 열려요". "여기까지만 무료", "더 보려면" 같은 표현을 쓰지 않는다. 광고처럼 보이지 않게 다른 카드와 같은 테두리·글꼴을 쓴다.
- 사용 컴포넌트: 제품 전용(.story-head, .story-progress, .archetype-card, .evidence, .story-empty, .spine, .spine-item, .paid-card), base(.btn).

## 애니메이션 명세 (2차)
- 원칙: ① transform·opacity 위주(모바일 성능). 흐림(filter)은 화면 전환·제목 등장처럼 한 번뿐인 곳에만. ② 긴 글 본문 뒤에서 계속 움직이는 것 금지 — `body.is-reading`이면 우주 배경의 모든 움직임 정지, 유성·먼지 숨김, 밝기 45%. ③ 한 번 재생하는 공개 연출은 JS가 class를 붙이는 순간 시작(아래 "트리거"). ④ `prefers-reduced-motion: reduce`이면 base.css가 모든 애니메이션·전환을 즉시 끝낸다 → 최종 모습이 곧바로 보임. 계속 도는 것(유성·먼지·궤적)은 숨김.
- 이징 토큰(base.css): `--ease-reveal` cubic-bezier(0.16,1,0.3,1) 빠르게 나와 천천히 멈춤 / `--ease-out` (0.2,0.8,0.2,1) / `--ease-in-out` (0.6,0,0.3,1) / `--ease-spring` (0.34,1.56,0.64,1) 살짝 튕김. 시간 토큰: `--dur-reveal` 650ms, `--stagger` 90ms.

## developer 전달 사항

### 바뀐 연결 방식 (기존 app.js 대비)
- 기존의 `data-t / data-h / data-list / data-ph / data-aria` 속성은 새 마크업에 넣지 않았다. 문구는 모두 data.js로 옮기되, 연결 방식(기존 속성 방식을 다시 붙이든, JS로 채우든)은 developer가 정한다. 문구 요소에 data-t 같은 속성을 추가하는 것은 괜찮다(class·배치는 바꾸지 말 것).
- 화면 전환: `id="screen-<이름>"` 유지. 현재 화면 class는 `active` → **`is-active`**. 화면 이름이 늘었다: `hub`(기존 home), `rune-intro`, **`rune-input`**(신규), `rune-ritual`, `rune-result`, `star-intro`, **`star-input`**(신규), `star-ritual`, `star-choose`, `star-result`, **`story`**(신규).
- 이동 버튼은 기존처럼 `data-go="<화면 이름>"` 속성을 쓴다(이동 전용 속성으로 유지).
- 화면이 바뀔 때 `body`의 `data-room`을 새 화면의 `data-room` 값(hall/rune/star)으로 바꿔 준다(배경 빛깔). 결과 화면에서는 `body.is-reading`, `topbar.is-reading`.
- 정적 검토 모드: `body.is-static-preview`를 지우면 모든 화면이 숨고 `.is-active`만 보인다. `[data-preview-only]`(별 바퀴 견본)와 `<dialog>`의 `open`·`data-preview`, 토스트의 `is-active`도 정리할 것. 자리표시 `[초안]` 문구는 data.js 값으로 바뀐다.
- 기존 id 가운데 바뀐 것: `#rune-name`, `#star-name`은 유지. `#star-date`(type=date) → 숫자 3칸 `star-year/month/day`, `#star-time`(type=time) → `star-hour/minute`. `#pouch`·`#ring-fill`(SVG 고리) → `rune-pouch`·`rune-ring`(24자 고리, `--progress`). `#stones`는 JS가 만들던 돌 마크업이 이제 HTML에 고정 3개. `#wheel` → `data-js="star-wheel"`(같은 SVG, 같은 class 규칙). `#rune-result`·`#star-result` 컨테이너에 통째로 innerHTML을 넣던 방식 → 결과 틀은 HTML에 있고 각 자리에 값을 채운다(장 본문 `chapter-body` 안의 단락·소제목·인셋은 JS가 만들어 넣어도 된다. 이때 아래 class를 그대로 쓸 것).
- `.card`/`.shown` 순차 등장 효과는 새 결과 틀에서 쓰지 않는다. 대신 (2차) `.chapter.is-in`과 `[data-reveal].is-in`(한 번, 650ms)을 쓴다. JS로 만들어 넣는 장 본문의 문단·소제목·인셋에는 `data-reveal` 속성을 붙이고 관찰할 것(정적 마크업에서는 떡밥·인용에만 붙어 있음).

### (2차) 바뀐 연결 지점
- **우주 배경**: 새 요소 `.cosmos`(JS 연결 없음). 기존 `canvas#sky` 반짝임 코드는 그대로 둬도 된다(그 위에 겹침). 스크롤 시차를 쓰려면 `:root`에 `--scroll`.
- **룬 고리 진행값**: `--progress`를 `rune-ring`이 아니라 **`rune-cast`**(`.cast`)에 준다. 고리·서리 띠·주머니 인장·기운이 모두 이 값을 물려받는다. `rune-ring`은 이름 유지, 값은 주지 않음.
- **룬 글자 → SVG 획**: `rune-stone-glyph`는 이제 텍스트 요소가 아니라 `<use>` 요소다. 글자를 넣는 대신 `href="#rune-<이름>"`을 바꾼다. 이름은 data.js RUNES의 `latin`을 소문자로 (fehu, uruz, thurisaz, ansuz, raidho, kenaz, gebo, wunjo, hagalaz, nauthiz, isa, jera, eihwaz, perthro, algiz, sowilo, tiwaz, berkano, ehwaz, mannaz, laguz, ingwaz, dagaz, othala). 결과 캡처 카드의 룬 3개도 같은 방식: 새 이름 `result-glyph` ×3(`<use>`).
- **별 바퀴**: 도형을 JS로 그리던 기존 코드(buildWheel)는 **지운다** — 바퀴는 index.html에 정적 SVG로 들어 있다. 회전도 JS `style.transform` 대신 CSS가 한다: `star-dial`에 `--moon-deg`, 화면에 `is-running`/`is-landed`. 새 이름: `star-dial`, `star-nak` ×27(`data-n` 0~26), `star-moon`, `rashi-label` ×12(텍스트는 data.js RASHIS의 `ko`에서 "자리"를 뺀 값으로 채워도 되고, 지금 값이 같으면 그대로 둬도 됨).
- **새 이름**: `warp`(포털 진입 빛).
- 이름은 그대로지만 역할이 늘어난 것: `result-capture`·`story-archetype`·`story-progress`(`.is-revealed`), `result-chapter`(`.is-in`).

1. **(1-A) 글꼴 버전 확인**: `@fontsource/gowun-batang`, `@fontsource/cinzel`, `@fontsource/noto-sans-runic`이 jsdelivr에 실제로 있는지, 존재하는 버전으로 index.html의 `5.2.5`를 바꿔 고정할 것(패키지마다 버전이 다를 수 있음). 각 CSS가 참조하는 woff2가 같은 패키지 안에서 열리는지, 한글 unicode-range 분할 파일이 받아지는지 확인. 가능하면 SRI(integrity)도 붙일 것.

## 판단 기록 (운영자 확인용)
- **(2차) 운영자 위임으로 확정**: 아래 7개(공유 버튼 두 곳, 밤 테마 고정, Cinzel = 영문 장식 1개 허용, 시작·입력 분리, 지우기 확인 대화상자, 유료 카드 "3,900원 · 곧 열려요", 장 번호 구분)는 모두 확정됐다.
- **(2차) 별자리 모양**: 27개 달의 집 별자리는 칸마다 별 2~4개를 정해진 규칙(고정 난수)으로 배치한 장식이다. 실제 나크샤트라 별 배치를 그린 것이 아니므로, 화면 문구에서 "실제 별자리 지도"라고 말하지 않는다(copywriter 전달).
- **(2차) 룬 획 모양**: 24자 획은 엘더 푸사르크의 일반적인 모양을 단순한 직선으로 옮긴 것이다(페르트로 ᛈ는 단순화). 고리의 룬 24자(Noto Sans Runic 글꼴)와 획 모양이 조금 다를 수 있다 **[화면 확인 필요]**.
- **공유 버튼 두 곳**: designer.md는 "캡처 → 공유 → 상세", 기획서 화면 흐름은 "캡처 → … 4장 … → 면책 → 공유" 순서다. 결과가 10분 글이라 둘을 모두 지키도록 캡처 카드 아래에 작은 보조 버튼, 면책 문구 아래에 주요 버튼을 두었다(주요 버튼은 하나).
- **밤 테마 고정**: 운영자가 좋아하는 밤하늘 컨셉을 지키려 `data-theme="night"`로 밝은 모드 사용자에게도 어두운 화면을 보여 준다. 다크 모드 사용자에게는 그대로 맞고, base.css에는 다른 제품용 밝은 테마도 있다.
- **Cinzel**: "한국어 글꼴 최대 2개"에는 한국어 글꼴 Gowun Batang 1개만 센다. Cinzel(영문 장식)을 합쳐도 웹폰트 2개라 엄격하게 읽어도 한도 안이다. "한국어 글꼴만 쓴다"를 영문 장식 글꼴까지 금지로 읽는다면 Cinzel을 빼고 Gowun Batang으로 대체할 수 있다(eyebrow가 덜 고전적으로 보임).
- **시작·입력 화면 분리**: 기획서 화면 흐름(1. 시작, 2. 입력)대로 나눴다. 탭이 하나 늘지만 두 화면 모두 주요 버튼이 스크롤 없이 엄지 자리에 있다.
- **"내 정보 지우기" 확인 단계**: 한 번 누르면 이야기 전체가 지워지므로 확인 대화상자를 두었다(새 기능이 아니라 같은 버튼의 실수 방지).
- **유료 카드의 가격 표시**: 1단계에는 결제가 없어 "3,900원 · 곧 열려요"로 둔다(2차 확정). 결제 전 고지(환불 조건 등)는 6단계에서 결제 화면과 함께 설계한다. 가격을 미리 보이지 않게 하려면 `story-paid-price`를 숨기면 된다.

- 상단 막대: "내 정보 지우기"가 한 줄인지(360px), 허브에 장 표시·진행률이 없는지

- 움직임(정적 캡처로는 안 보임, 실제 기기에서): 포털 진입 빛, 화면 전환 흐림, 봉인 풀기, 장 등장, 별 의식 5초, 원형 문장 그리기. 저사양 폰에서 버벅임 여부

### 발견한 문제와 원인
1. **룬 결과 캡처 카드의 돌 3개에 룬이 안 보임** — 원인은 **CSS(designer)**, JS 아님. `result-glyph`의 `href="#rune-<code>"` 연결은 맞다(app.js 623줄, data-runes.js code 24개와 index.html `<symbol>` 24개 이름 일치 확인). 최소 재현 페이지에서 **움직임 끔: 획 보임 / 움직임 줄이기 켬: 획 안 보임**으로 재현됨. 예전 base.css의 움직임 줄이기 규칙(길이만 0.01ms로 줄임)에서 선 그리기(`stroke-dashoffset` 1→0) 애니메이션의 끝값이 `<use>`로 부른 SVG 획(그림자 트리)에 반영되지 않고 시작값(획 숨김)에 머묾(Chromium 동작으로 추정, 원인 세부는 미확인).
2. **첫째 장 머리(로마 숫자·라벨·제목·시간)가 비어 보임** — 원인 두 가지. ① 움직임 줄이기에서도 `animation-delay`(0.2~0.5초)가 남아 지연 동안 숨김(developer 지적과 같음). ② 장 머리는 `.js-reveal` 아래에서 장이 화면에 들어와 `.is-in`을 받기 전까지 숨김인데, 움직임 줄이기 블록에서 이 숨김을 되돌리지 않았음. 전체 페이지 캡처는 스크롤 없이 찍혀 첫째 장이 "화면에 들어온" 적이 없음.
3. **별 결과 장 머리** — 운영자 캡처(flow.png 가운데 열)에서 I·II 장 머리가 보임. 같은 원인의 영향을 받는 구조라 위 수정이 똑같이 적용됨. flow.png 왼쪽 열(상단 막대만 있고 본문이 빈 화면)은 무엇을 찍은 것인지 알 수 없어 미확인.

### designer가 직접 고친 것 (style.css, 마크업)
- **common/base.css 움직임 줄이기**: `animation-duration: 0.01ms` 방식 → `animation: none !important; transition: none !important`. 지연·획 그리기 문제가 함께 사라진다. 원칙("애니메이션 없는 기본 스타일 = 최종 모습")을 docs/design-system.md에 적음. base.css를 쓰는 제품은 strange-oracle뿐(grep 확인). 이 원칙에 맞는지 제품 키프레임을 다시 봤다: 봉인·빛 번짐·빛줄기·포털 진입 빛은 기본이 투명(움직임 줄이기에서는 나타나지 않음 = 의도), 바퀴·달은 기본이 착지 위치, 아치·노드 점등은 기본이 점등 상태.
- **style.css 움직임 줄이기 블록**: 장 머리 숨김(`.js-reveal .chapter:not(.is-in)`)과 장식선 `scaleX(0)`을 되돌림, 별 의식 진행 막대는 가득 찬 모습으로.
- **캡처 카드 메타**(`.capture__meta`): 최대 폭 26em + 가운데 정렬 + `text-wrap: balance` + 줄 간격 — 이름이 길어도 두 줄로 고르게 꺾이고 넘치지 않는다.
- 재현 확인(designer, 헤드리스 Edge): 수정 뒤 움직임 줄이기 켬에서 룬 획·장 머리·10자 이름 메타가 모두 보임. 움직임 끔에서는 기존대로 획이 그려지고, 장 머리는 스크롤로 들어올 때 나타남(정상 동작).
- 주의: 움직임을 켠 상태로 **스크롤 없이 전체 페이지를 한 장으로 캡처**하면 첫째 장 아래의 장 머리·문단은 여전히 비어 보인다(아직 "보인 적이 없어서"). 오류가 아니라 스크롤 등장 효과다. 캡처는 움직임 줄이기를 켜고 찍으면 전부 보인다.

## 디자인 방향 (네 방)
- **여섯 가지 손맛이 겹치지 않게**: 룬 = 쥐고 흔들고 뒤집기(누르고 있기), 별 = 하늘이 되감기는 걸 지켜보기, **오검 = 손끝으로 껍질에 긋기(쓸어내리는 속도가 곧 새기는 속도)**, **데칸 = 멈춘 돌 원반 위를 그림자만 똑딱 넘어가는 걸 지켜보기(도는 건 원반이 아니라 빛)**, **촐킨 = 맞물린 두 톱니가 서로 반대로 도는 기계적 순환**, **시빌라 = 두루마리를 집어 불꽃으로 옮겨 놓기 → 숨은 글자가 떠오름**.
- 신비로움: 방마다 배경 층 — 오검 = 멀리 선 자작나무·안개·떠도는 빛 알갱이, 데칸 = 새벽→정오로 차오르는 금빛 하늘·모래 언덕·날리는 모래, 촐킨 = 위 모서리 정글 잎·청록 빛 알갱이, 시빌라 = 양옆 대리석 기둥·촛불이 바닥을 비추는 빛. 모두 CSS만.
- 문화 존중: 촐킨의 스무 문양은 **그림을 지어내지 않고** 카르투슈 틀에 이름만 새긴다(살아 있는 달력의 도상을 임의로 그리지 않기 위해). 숫자는 실제 마야 막대·점 표기(점=1, 막대=5). 오검은 필사본식 획(줄기 + 획 1~5개, 4묶음).

### 0. 허브 (여섯 방) [캡처 확인]
- 레이아웃: 달 문장(64→52px) → eyebrow → 로고 → 부제 → **포털 6개 2열×3행(장 순서 I~VI: 오검·별·데칸·촐킨·시빌라·룬)** → 나의 이야기 진행 카드(아치 6개, 기존) → 소개 글 → 광고.
- 순서는 우선순위가 아니라 "나의 이야기" 장 번호(문 위 로마 숫자 I~VI로 표시).
- 문: 포털 104→76px, 방 이름 22→19px(2줄까지, balance — "시빌라 신탁의 방"은 2줄), 출신 13px, 설명 14px 2줄. 같은 줄 두 문 높이는 grid가 맞춘다.
- 360×640: 첫 줄 포털 2개 전체 + 둘째 줄 포털 윗부분이 첫 화면에 보여 스크롤을 부른다. 여섯 문 색이 서로 구분된다.
- 포털 6개 동시 회전 부담 때문에 **소용돌이 blur 필터를 뺐다**(마스크로 가장자리 처리). 짝수 문은 반대로 돌고, 맥동은 문마다 0.53초씩 어긋남.
- "아직 봉인된 방" 섹션은 `.is-hidden`(app.js가 `hub-closed`를 찾아 지우면 오류) → developer가 JS와 함께 삭제.

### 1. 방 시작 (네 방) — 틀은 룬·별과 같음
- 방 상징: 오검 = 자작나무 껍질 조각 위 오검 획(베흐) 그리기 / 데칸 = 해시계 아이콘 / 촐킨 = 톱니 아이콘(40초에 한 바퀴) / 시빌라 = 월계관 + 촛불.
- 알약 "나의 이야기 N장 · 챕터"는 기존 `room-chapter-num`(data-n 1/3/4/5)이 채운다.

### 2. 입력
- 오검: 이름 1칸 + 안내 한 줄 + 오류 `ogham-error`. 개인정보 안내 `privacy.noticeName` 재사용.
- 데칸·촐킨: 별의 방 날짜 3칸과 같은 마크업(시각 칸 없음) + 방별 안내(`<방>.input.dateHint`) + 오류 `<방>-error`. `privacy.noticeBirth` 재사용.
- 시빌라: 주제 칩 5개(2열, 마지막 "나 자신"은 한 줄 전체) + 질문 textarea(2줄, maxlength 60, 글자 수 `sibyl-question-count`). 저장된 정보 카드 없음. 안내는 **새 문구** `privacy.noticeQuestion`. 질문은 sessionStorage에도 넣지 않는다(운영자 결정 25번).

### 3-O. 오검 의식 — 자작나무 껍질에 새기기 [캡처 확인: 시작·중간·완료]
- 레이아웃: 안내 2줄 → **껍질**(124×min(380px,50dvh), 흰 자작나무·검은 껍질눈) → 로마자 이름 한 줄 → 안내 한 줄.
- 껍질 안: 점선(새길 길) → 이름 글자 수만큼 세로로 나눈 칸마다 새길 자리 점 → 빛나는 칼끝(처음엔 숨쉬며 아래 화살표).
- 조작: 껍질 위에서 **아래로 쓸어내린 비율 = `--carve`(0~1)**. 칼끝이 따라 내려오고, 줄기가 파이고, 각 글자 획이 칼끝이 지나는 순간 그려진다(CSS가 글자마다 `--cut` 계산). 손을 떼도 되돌아가지 않음(룬 주머니와 다른 점). 누를 때마다 한 글자씩 새기는 방법도 제공(접근성).
- 다 새기면 `.is-carved`: 글자가 위에서부터 80ms 간격으로 하얗게 빛남 → 껍질이 어두워짐 → **뿌리 글자**(결과 오검 한 자)가 떠오르며 획이 그려짐 → 이름 알약. 약 3.4초 뒤 결과.
- 오검은 전통적으로 아래에서 위로 읽지만 이 의식은 쓸어내리는 동작에 맞춰 위→아래로 새긴다. 화면 문구에서 "전통 방식대로"라고 말하지 않는다(copywriter 전달).

### 3-D. 데칸 의식 — 정오의 해시계 [캡처 확인: 착지 상태]
- 레이아웃: 안내 + 날짜("1995. 3. 21. 정오") → **사암 원반**(min(320px,86vw)): 햇살 눈금 72개, 금빛 테두리, 36칸(12궁 경계는 긴 선), 칸마다 데칸 별, 해시계 시간선, 가운데 오벨리스크 → 데칸 이름 → 상식 카드 → 5초 진행 막대 → 모래 언덕.
- 연출: **원반은 돌지 않는다.** 그림자(긴 쐐기)와 반대편의 해가 한 팔로 원반 둘레를 돈다. 360° 전부터 **한 칸(10° ≈ 열흘)씩 똑딱**, 점점 느려짐(18칸 73ms → 12칸 110ms → 5칸 220ms → 마지막 한 칸은 미끄러지듯). 동시에 하늘이 새벽빛→정오빛, 36개 별이 하나씩 켜짐. 4.4초 `.is-landed`: 그림자가 가리킨 칸이 금빛, 그림자 끝에 빛, 이름이 떠오름.

### 3-D′. 데칸 후보 고르기
- 별의 방 후보 화면과 같은 틀(`.star-choose .day-line .choice`), 2칸·2장. 색 1 = 호박빛(sand), 2 = 터키석(jade), 번호 함께 표시.

### 3-T. 촐킨 의식 — 맞물린 두 돌 톱니 [캡처 확인: 착지 상태]
- 레이아웃: 안내 2줄 → **톱니 한 쌍**(폭 min(340px,100%)): 왼쪽 작은 톱니(이 13, 금빛 막대·점 숫자), 오른쪽 큰 톱니(이 20, 카르투슈 20개에 문양 이름) — 맞물린 자리에 바늘과 빛 고리 → 그날 이름 → **260일 돌판**(가로 20문양 × 세로 13줄 = 점 260개) → "260일 가운데 N번째 날" → 진행 막대.
- 연출: 40일 전 자리에서 **서로 반대 방향으로**(큰 것 720°, 작은 것 1107.69° = 20:13) 같은 이징으로 돌아 맞물린 채 멈춤(4.2초). 돌판 위로 빛 띠 3회. `.is-landed`: 맞물림 번쩍, 그날 카르투슈·숫자 점등, 톱니 가운데(돌지 않는 원)에 숫자와 문양 이름, 돌판에 세로·가로 띠와 그날 점.
- 카르투슈 글자는 맞물린 자리(왼쪽)에서 똑바로 서도록 기울였다. 다른 자리 글자는 거꾸로 보일 수 있다(새긴 돌, 의도).

### 3-V. 시빌라 의식 — 두루마리를 촛불로 [캡처 확인: 말림·끄는 중·펼친 최종]
- 레이아웃: 안내 2줄 → 물어본 것 카드(카테고리 알약 + 질문, 비면 줄 사라짐, 최대 2줄) → **무대 372px**: 말린 두루마리(양피지 뭉치·나무 손잡이·붉은 봉랍), 점선 안내, 촛불(흔들리는 불꽃·후광), 대리석 제단 → 안내 한 줄.
- 조작: 아래로 끌면 `--near`(0~1, 172px 기준)만큼 내려오고 불꽃·후광이 커지고 종이가 데워진다. 0.8 이상에서 놓거나 한 번 누르면 `.is-warming`: 불꽃 위에 자리 → 봉랍이 부서져 떨어짐 → 종이가 **아래(불꽃 쪽)에서 위로** 펼쳐짐 → 번호와 신탁 문장이 아래에서부터 흐린 갈색→불빛에 달아오름→짙은 갈색으로 떠오름(비밀 잉크). 약 4.4초 뒤 결과.
- 오검(표면을 따라 긋기)과 다른 점: 물건을 옮겨 놓는 동작, 결과가 "새기는" 게 아니라 "이미 있던 글자가 드러나는" 것.

## 디자인 방향
- 무료 = **펼친 두루마리**(금빛 테두리, 글자가 보임) / 유료 = **밀랍 인장으로 봉인된 칸**(인장 + 흐린 별자리 점선 줄, 글자 없음). 같은 hall(금) 강조색 안에서 열림과 닫힘만 다르게 보인다.
- 봉인 해제 의식은 여섯 방 의식과 겹치지 않게 **별자리 고리 위 인장 여섯 개가 차례로 갈라지고 그 자리에 별이 켜진다**(약 3초). 방의 재료(돌·달·나무·해시계·톱니·촛불)는 쓰지 않는다.
- 조르지 않기: 방 결과에는 글자 링크 한 줄, "나의 이야기"에는 기존 카드 하나만 둔다. 팝업·배너·남은 시간·할인은 없다. 미리보기·결제·리포트 화면에는 광고 자리가 없다.

### 6-P 미리보기 (위→아래, 광고 0)

6. `.disclosure` 결제 전 고지(**접지 않음**, `<details>` 금지): 받는 것·분량·가격(+부가세 ◯◯)·이용 방법·청약철회·환불·미성년자(필요 없으면 JS가 `deeper-minor`를 숨김) → 동의 체크 `.check.consent`
7. `.pay-alert`(실패·취소 때만) → `.pay-cta`: 결제 버튼 + 상태 한 줄(aria-live)
8. `.biz-info`: 사업자 정보 dl(◯◯) + 정책 링크 3개
- 상태: 버튼 `disabled`(미동의·입력 오류) / `.is-loading`+`aria-busy`(결제창 여는 중) / `.pay-alert` 보임(실패·취소, 오류 코드는 보이지 않음). 입력 오류는 기존 `.field__error` 문구 규칙을 따른다.
- D-2: 고지 블록과 결제 버튼 사이에는 `.pay-alert`(실패 때만) 말고는 아무것도 두지 않는다.

### 6-U 봉인 해제 의식
- 띠 → 상태 문구(aria-live) → `.unseal-ring`(점선 육각 별자리 + 인장 6개 `--i:0~5` + 가운데 빛) → 건너뛰기.
- 타이밍: 인장 i는 `300ms + i×380ms`에 갈라지고(560ms), 200ms 뒤 별이 켜진다. 전체 약 3.0초 = `--unseal-ms`.
- **기본 스타일 = 최종 모습**(모두 갈라지고 별 6개 켜짐). `.is-running`일 때만 "온전 → 갈라짐"을 재생한다. 그래서 움직임 줄이기(base.css가 애니메이션을 끔)에서는 곧바로 최종 모습이 보인다.
- 오류: 화면에 `.is-error` + `unseal-error`가 보인다(고리가 흐려지고, 주문번호=영수증 코드 표시, 다시 시도 버튼).

### developer 요청
1. 결제가 꺼져 있으면(`api/config`가 없음·실패·off) 새 요소는 모두 `.is-hidden` 그대로 두고, 세 화면으로 가는 길을 만들지 않는다(D-9).
2. 마크업의 `[초안]` 중 data-t가 **없는** 자리(목차 이름·분량·맛보기, 영수증 코드 견본, 리포트 본문 견본)는 JS가 반드시 덮어쓰거나 지운다. 유료 문장은 절대 마크업이나 data.js에 넣지 않는다(D-4).
3. 1장·2장·궁합 방 목록의 견본은 `<template>`로 옮겨도 된다(class 이름은 유지).
4. 영수증 코드는 4자씩 `<span>`으로 끊어 넣는다. 복사하는 값은 원문 코드다(하이픈 포함 여부는 developer가 정한다).
5. 봉인 해제 시간 `--unseal-ms: 3000ms`와 JS 타이머를 맞춘다. 건너뛰기나 움직임 줄이기면 곧바로 6-R로 간다.
6. 소장 카드는 위 "공유 카드: 유료 소장판" 명세대로 share-card.js에 테마를 추가한다(공통 부품 변경이므로 쓰는 제품을 확인하고 보고).
7. 인장 `<symbol id="i-seal">`은 `#screen-deeper` 바로 앞 스프라이트에 있다. `<use>` 안쪽에는 CSS 선택자가 닿지 않으므로 색은 symbol 안의 style 속성(`var(--wax)` 등)으로 준다. 기존 결과 캡처의 `.seal`과 이름이 겹치지 않게 새 인장은 `.wax-seal`을 쓴다.

### 화면별 명세
**상단 막대(모든 화면)**: 왼쪽 "입구" 버튼(청동 테두리 알약, 입구 문 아이콘 + 글자, 높이 44px, 입구 화면에서만 숨김) · 가운데 라벨(방: "Ⅲ 데칸의 방 3/6", 책: "Ⅳ 촐킨의 방 · 5/9") · 오른쪽 [목차(책에서만)] + 내 정보 지우기. 방 화면의 네 칸 읽기 진행률은 없앴고, 진행률은 책 전용 9칸이다.

**입구** (위→아래): ① 머리(문양·로고·요약 한 줄·자물쇠 아이콘 + 개인정보 한 줄) ② 주 버튼(로마 숫자 명판 + "Ⅲ 데칸의 방 열기", 높이 56px, 은은한 숨쉬기 빛) ③ 여정 한눈에: 칩 3개 → 여섯 방 줄(2열×3행, 방 색 상징 원 + 짧은 이름 + 무엇을 읽나) → "여섯 조각이 모여…" 한 줄 ④ "순서대로 하나씩" 한 줄 + 여섯 고대 문(7단계 스타일 그대로) ⑤ 지금까지의 이야기 카드(제목 + N/6 막대, 지금 원형, 마친 방 줄 = 상징·방 이름·결과 이름 + key 한 줄 말줄임, 안 연 방은 "?" 점선 원으로 흐리게, 맨 아래 "나의 이야기 전체 보기 →") ⑥ 한 권의 책 카드(책 그림 + 밀랍 인장, 제목·설명, 6/6 전 여섯 칸 핍 + "N/6", 버튼 하나) + 접힌 "영수증 코드가 있어요 ▾" ⑦ 자주 묻는 것 6문답(펼친 채, Q 표시) ⑧ 광고 1개 ⑨ 내 정보 지우기 안내 한 줄.
360×800 첫 화면(스크롤 전)에 요약·주 버튼·칩·여섯 방 줄까지 보인다(캡처 확인).

**방 시작**: 오검·별·데칸·촐킨에 "1995.3.21 기준으로 봅니다 · 바꾸기" 한 줄(`room-saved`, 값이 있을 때만). 별 엠블럼은 새 `#icon-star` symbol(획 도형)로 바꿨다.
**의식**: 별·데칸·촐킨·시빌라·룬에 흐린 힌트 "누르면 바로 보기"(`ritual-skip`, 화면 아래 고정). 오검(직접 새기기)은 없음.
**방 결과**(8-1 표 순서): 결과 카드 → 공유(카드 아래 하나, 보통 크기 보조 버튼) → 원형 한 줄(위로 올림) → 공감 카드 → **핵심 풀이**(가운데 선 제목, 17px/1.85, 첫 단락 강조, 사실 목록 상자, 맺음 문장 칸) → **책 한 줄**(책 아이콘 + 떡밥 + 안내, 위아래 점선, 링크는 ready·owned일 때만) → 문화 상식 → 면책 → 글자 링크 "결과 이미지 저장·공유 · 정보 바꿔 다시 보기"(룬은 공유만, 시빌라는 "다른 신탁 받기" 버튼 + 안내 + 공유 글자 링크) → 이야기 다리 + 다음 방 문 → 광고 1개(맨 끝). 장 목차·봉인 블록·장 사이 광고·"나의 이야기 보기" 보조 링크는 0개.
**미리보기**: 제목·설명을 "한 권의 책"으로, 목차에서 숨은 장 항목 삭제(제1부 안으로), 번호를 "1부/2부"로. 기존 "방을 더 돌고 결제하면…" 문장을 `deeper.bookFix`로 교체. 6/6 전 잠금 블록 `book-gate`(핍 + "(N/6)" + 다음 문 열기)를 결제 버튼 자리 위에 두었다.
**책**: 영수증 카드 → 표지(소장판·원형·여섯 상징·나눠 읽기 한 줄) → 이어 읽기 줄 → 목차(9항목: 여는 글·여섯 방·제2부·닫는 글, 읽는 시간, 체크 원) → 여는 글 → 제1부 머리 → 방 6개(상징 원·방 이름·결과 이름·key → Ⅰ~Ⅳ장 청동 번호판 → 숨은 장은 점선 상자 + 인장 → "목차 / 다음 방 →") → 제2부 머리 → 시기별 흐름·궁합·원형 심층 → 닫는 글 → 면책 → 소장 카드 공유(주) + "나의 이야기로"(글자) → 영수증 다시. 목차 시트는 아래에서 올라오는 dialog.
긴 글 피로 대책: 본문 17px, 줄 간격 1.9, 34em 폭, keep-all, 단락 간격 1.2em, 방마다 큰 여백 + 가운데 머리, 장 번호판으로 위치 파악.

### 상징 떠오름 (8-3)
오버레이 `.sigil-rise` 하나(방별 상징 6개를 품고 `data-room`으로 하나만 보임). 1200ms: 0~250 문짝(기존) / 150~650 획 그리기(stroke-dashoffset 1→0, 문 안 상징 자리에서) / 650~1000 가운데(50vw, 42vh)로 1.45배 떠오르며 방 색 장막이 덮음 / 1000~1200 도착 엠블럼 자리로 착지, 장막 걷힘. 시빌라는 월계관이 늦게 페이드. 누르면 `.is-skipped`(200ms 착지). 마친 방 다시 보기 `.is-flash`(500ms 번쩍, 획 없음). 움직임 줄이기: 이동·확대·획 없음, 가운데 페이드 인 200 + 아웃 200 = 400ms, 기본 상태 = 오버레이 안 보임·엠블럼 제자리.

1. **원본**: 지금처럼 JS가 `book-source`(hidden) 안의 기존 훅(report-open, book-ch1~4, book-hidden, report-timeline, report-match, report-deep-*, report-close …)을 채운다. 채우는 코드는 그대로 둔다.

| 버튼 | `book-prev` / `book-next` click | 이전 / 다음. 처음·끝에서 `disabled` |
| 키보드 | document `keydown` (책 화면이 활성, dialog 닫힘, 입력칸 포커스 아님) | ←/PageUp 이전, →/PageDown/Space 다음, Home 1쪽, End 마지막 쪽 |
| 목차 | `book-toc-open`(상단 막대) → `book-toc-sheet`, 목차 쪽의 링크 | 링크 기본 이동 막고 그 장의 시작 쪽으로 즉시 이동, 시트 닫기, 포커스는 그 쪽(`tabindex=-1`) |
| 표지 | `book-open-btn` / `book-resume` click | `data-view="pages"`, 1쪽 / 저장된 쪽 |
| 이어 읽기 저장 | 쪽이 바뀔 때마다 | sessionStorage에 **쪽 번호만**(결정 53). 다시 열 때 총 쪽 수를 넘으면 마지막 쪽으로 |

- 화면낭독기: 쪽마다 `aria-label="12쪽 / 48쪽"`(키 `book.pageAria`), 쪽이 바뀌면 `book-live`에 "12쪽 / 48쪽, Ⅰ 오검의 방" 한 번. 버튼 `aria-label` "이전 쪽"/"다음 쪽". 탭 영역은 `aria-hidden`+`tabindex=-1`(같은 기능을 버튼이 가짐).
- 보이는 포커스: 버튼·쪽은 청동 2px 외곽선, 종이 위 목차 링크는 붉은 잉크 2px 외곽선(모두 `:focus-visible`).
- 상단 라벨 `read-label`: 지금 쪽의 부·방 이름만(쪽 번호는 쪽 아래에 있으므로 뺀다).
- 진행 줄 `book-track-fill`: `--p = 지금 쪽 / 총 쪽`.

### 움직임 줄이기 (prefers-reduced-motion: reduce)
- JS는 `matchMedia('(prefers-reduced-motion: reduce)')`가 참이면 turn class를 **붙이지 않고** `is-current`만 바꾼다(animationend가 오지 않으므로 기다리지 않는다).
- CSS도 방어: turn·그늘 애니메이션 `none`, `is-turn-next`는 즉시 숨김, 진행 줄 전환 없음. 모든 쪽의 기본 상태가 최종 모습.
- `body.is-reading`의 배경 정지 규칙은 그대로.

### 캡처 기록 (headless Edge, 360px, 마크업 견본 + 캡처 스크립트로 class만 바꿔 확인)
- `d53-800-1-cover` 표지(가죽·금박·이어 읽기), `d53-800-2-page12` 방 첫 쪽(장식선·방 이름·결과 이름·Ⅰ장·머리글자), `-page13` 본문 쪽(머리글·들여쓰기·쪽 번호), `-page16` 방 안 Ⅱ장 시작, `-page2` 목차 쪽(9항목 한 쪽), `d53-800-3-turn-mid` 넘김 260ms 정지(종이가 제본 축으로 휘며 넘어가고 아래 쪽이 드러남), `d53-640-*`, `d53-800r-*`(움직임 줄이기: 애니메이션 없음, 넘기는 쪽 즉시 숨김).
- 가로 넘침: 모든 캡처 scrollWidth 360 = innerWidth 360. 세로도 문서 높이 = 화면 높이(800/800, 640/640) → 바깥 스크롤 없음.
- 견본 본문은 800 높이에서 547/547px로 딱 맞음. 640 높이에서는 견본이 넘치며(보이는 부분은 잘림) 실제로는 쪽 나누기가 다음 쪽으로 보낸다.
- 견본 문장은 유료 본문이 아닌 설명용 문장으로 새로 썼다(build-dist의 "공개 폴더에 서버 전용 내용" 검사 통과).
- 미확인: 실제 결제 흐름에서의 쪽 나누기·스와이프·키보드 포커스 모습(구현 전), 실제 기기 사파리의 3D 넘김 성능.
