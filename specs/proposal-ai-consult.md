# 제안: 일곱 방의 AI 심층 상담 (strange-oracle)

- 상태: **보류** (운영자 결정 2026-11-01 — "지금은 지금 상품을 다듬는 게 우선")
- 원본: 운영자 기획 초안 「일곱 방의 AI 심층 상담」(2026-11-01, docx)
- 이 문서: 기획 초안 검토 결과와 다시 꺼낼 조건. 기획서(specs/strange-oracle.md)에는 아직 반영하지 않는다.

## 1. 아이디어 한 줄
일곱 방마다 그 전통의 해석 관점·말투를 가진 AI 상담자를 두고, 이용자가 자기 방 결과를 바탕으로 추가 질문을 할 수 있게 한다. 기존 일곱 방 체험과 책을 대체하지 않는 선택형 확장.

## 2. 보류한 이유
1. 지금 병목은 상품 수가 아니라 흐름이다: 만신 → 오검 넘어가는 비율 58%(42% 이탈), 결제 화면 → 결제 시작 15% (GA4 2026-10-26~31).
2. 표본이 작다: 책 구매 하루 약 1.5건. 구매자 한정으로 열면 한 달 약 45명만 써 봐서 판단에 두세 달 걸린다.
3. 브랜드 약속과 충돌한다: "입력한 것은 어디에도 보내지 않는다"(시빌라 질문 전송 0)가 신뢰의 바탕인데, AI 상담은 처음으로 이용자 글을 외부로 보낸다.
4. 1인 운영 부담: 금지 주제(건강·죽음·투자·이별 겁주기, 운영 규칙 8장) 답변을 계속 지켜봐야 한다.

## 3. 다시 꺼낼 조건 (2개 이상 맞으면 재검토)
| 조건 | 2026-11-01 | 목표 |
|---|---|---|
| 만신 → 오검 비율 | 58% | 70% 이상 |
| 결제 화면 → 결제 시작 | 15% | 25% 이상 |
| 책 구매 | 하루 약 1.5건 | 하루 3건 이상 |
| 구매자가 책을 실제로 읽음 (`so_book` read) | 미확인 | 구매자 절반 이상 |

비용 없이 먼저 볼 수요 신호: 인스타 스토리 투표("안내자에게 내 결과로 직접 물어볼 수 있다면?"), "만신의 풀이 더 듣기" 펼침 비율, 베다~시빌라 "이 방의 이야기 더 읽기" 클릭(`so_book_offer_click` room_more).

## 4. 검토 요약
### 강점
- 이미 계산된 결과 번호와 직접 쓴 해석 문장(무료 data-*.js, 유료 api/_paid/book/)이 있어, AI가 그 안에서만 답하게 묶을 수 있다(결과를 지어낼 위험 감소).
- 안내자 말투가 브랜드 가이드(design/strange-oracle-brand.md)에 이미 있다.
- "안내자에게 직접 물어보세요"는 광고 문구로 강하다.

### 약점·위험
- 책과 잠식: AI가 무료로 깊게 답하면 책을 살 이유가 줄어든다 → 처음엔 책 구매자 혜택으로.
- 오검·데칸·촐킨은 역사 자료가 적어 AI가 "고대의 의미"를 지어낼 위험 → 우리가 쓴 해석 문장 안에서만 답하게.
- 시빌라의 "적은 고민은 어디에도 남지 않아요" 약속과 섞이지 않게 별도 화면·별도 동의 필요.
- 자유 질문이 금지 주제로 쉽게 간다 → 거절 규칙 + 출시 전 시험 세트(금지 주제 20개 포함) 필수.

### 운영 규칙(CLAUDE.md)상 필요한 결정
| 규칙 | 충돌 | 필요한 결정 |
|---|---|---|
| 3장 서버 예외 | AI 상담 함수는 새 서버 기능 | "AI 상담 함수" 예외 추가 |
| 6장 개인정보 | 질문 글이 외부 AI(미국)로 감 | 전송 예외·동의 화면·국외 이전 안내·만 14세 미만 제외·보관하지 않음 |
| 8장 콘텐츠 | 금지 주제 답변 위험 | 거절 규칙·시험 통과 기준 |
| 9장 작업 흐름 | 기획 초안 단계 | 기획서 → 기획 검수 → 개발 |
| 기획 v6 | "AI 상담·구독 보류" | 재개 여부 |

이름·생년월일·태어난 시각은 보낼 필요가 없다. 결과 번호 + 질문 글만으로 충분하다.

## 7. 대안 (재개할 때 고를 것)
| | 0안: 질문 카드 (AI 없이) | 1안: 구매자 한정 AI (추천 MVP) | 2안: 상담권·전체 방 |
|---|---|---|---|
| 내용 | 결과마다 자주 묻는 질문 5개의 답을 미리 써서 검수, 책 함수로 제공 | 열람 코드가 있는 사람만, 1~2개 방(시빌라·만신), 질문 N번 | 상담권 판매, 일곱 방, 대화 저장, 스트리밍 |
| 개발 | 낮음(콘텐츠 중심) | 중간(함수 1 + 화면 1) | 높음 |
| 변동비 | 0원 | 월 수천 원 | 이용량만큼 |
| 개인정보 | 전송 0 | 질문 글 전송 → 규칙 예외 | 기록 저장까지 |

1안 구조 메모: `POST /api/consult { pass, room, 결과 번호, 질문, 최근 대화 ≤6턴 }` → 열람 코드 확인 → 남은 횟수(Blobs `consult/<코드 해시>` = { used, at }) → IP별 제한·질문 300자 → 고정 지시(캐시) + 방 페르소나 + 그 결과의 해석 문장 + 질문 → Claude API(키는 환경 변수만) → 금지 주제 검사 → 답변 + 남은 횟수. 질문·답변 원문은 저장하지 않는다. AI 장애 시 상담 버튼만 꺼진다. 측정 `so_consult` { step, room }.

## 8. 재개 때 운영자가 정할 것
1. 3장·6장 예외 추가(질문 글 외부 전송) 여부

3. 질문 횟수(열람 코드당)
4. 시험할 모델 후보와 월 비용 상한
5. 첫 방(추천: 시빌라 + 만신)
