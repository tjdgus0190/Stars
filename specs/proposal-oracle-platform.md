### 1.2 한국인에게 이미 익숙한 것 — 별도 평가

- **주역(#7)**: "낯선 점술관"의 핵심 매력은 "처음 보는데 내 얘기 같다"인데, 주역·육효는 이미 한국에서 무료 온라인 서비스가 다수 존재하는 대중적 점술이라(헬로사주, 도깨비운세, 60갑자 등) "생소함" 컨셉과 정면 충돌한다. 검색 수요는 높지만 경쟁이 이미 포화 상태다.
- **오미쿠지(#8)**: 일본 여행 경험(JNTO, 여행 매거진 다수)으로 이미 절반쯤 익숙해 신선함이 약하고, 포춘에이드가 "세계의 점술 시리즈"로 이미 다루고 있어 차별화가 어렵다.
- **사주·타로**: 이 제안서의 비교 후보에 아예 넣지 않았다. 앱 공장의 meta.json 카테고리에 "사주"가 별도로 있고("오컬트"와 구분), 타로는 국내에서 이미 완전히 대중화된 콘텐츠라 "낯선 점술관"의 정체성과 정반대다.

**결론**: #7, #8은 후보 비교표에는 남기되(참고용) 최종 추천 6개에서는 제외를 권장한다. #9, #10은 문화적 민감도가 너무 높거나(#9) 근거가 너무 약해(#10) 배제를 권장한다.

각 방을 다 돌면 결과를 하나로 합치는 "공식"이 필요하다. 3가지 안을 비교한다.

### 안 A. 공통 원소 매핑 (4원소/오행)
- **원리**: 방마다 나온 결과 유형(룬 24개, 나크샤트라 27개, 오검 20개 나무, 촐킨 20문양 등)에 원소(불/물/바람/흙 또는 오행)를 하나씩 배정하고, 여러 방 결과를 모아 "원소 균형표"를 만든다.
- **필요한 방**: 최소 2개, 많을수록 정밀.
- **최종 결과물**: 원소 균형 막대그래프/레이더形 공유 카드 + "불과 바람의 방랑자" 같은 한 줄 캐릭터명.
- **재방문 구조**: 방을 깰 때마다 프로필이 갱신되고, "아직 물의 기운을 못 만나셨어요" 식으로 다른 방 방문을 유도.
- **장점**: 시각적으로 직관적이고 재방문 동기가 뚜렷함.
- **단점**: 룬·오검 등은 전통적으로 4원소/오행 체계를 쓰지 않아 **임의로 지어낸 매핑처럼 보일 위험**이 크다. "고증에 없는 내용을 지어냈다"는 비판을 받기 쉽다.

### 안 B. 원형(운명의 원형) 매핑
- **원리**: 각 방의 결과 문구(예: 룬의 "you" 문장, 나크샤트라의 traits)에 미리 정한 8종 정도의 원형(전사·현자·연인·반항아 등) 태그를 하나씩 부여한다. 여러 방 결과를 합산해 가장 많이 나온 원형이 최종 결과가 된다.
- **필요한 방**: 방을 1개만 해도 결과가 나오게 설계 가능(타이브레이크 규칙 필요).
- **최종 결과물**: 원형 카드(원형 이름 + 각 방에서 나온 근거 요약).
- **재방문 구조**: "지금까지는 현자 쪽인데, 다른 방을 더 돌면 바뀔 수도 있어요" 식 유도.
- **장점**: 각 문화 고유 체계를 왜곡하지 않는다(원형은 "해석 레이어"일 뿐 각 문화 체계 자체를 건드리지 않음). 기존 데이터에 태그만 추가하면 되어 제작 부담이 상대적으로 작다.
- **단점**: 방을 적게 돌면 원형 판별이 엉성해 보일 수 있고, 원형별 카드 일러스트가 새로 필요하다.

### 안 C. 시간 흐름(인생 서사) 통합
- **원리**: 원소나 원형처럼 억지로 축을 만들지 않고, 방마다 결과를 "인생의 한 장(章)"으로 배치한다. 예: 오검=뿌리(근원), 베다=지금의 마음결, 촐킨=다가올 순환, 데칸=숨은 재능, 시빌라=오늘의 질문에 대한 답, 룬=과거·현재·미래. 방을 다 돌면 이 장들을 모아 "한 권의 이야기"로 보여준다.
- **필요한 방**: 이론상 몇 개를 하든 이야기가 이어지지만, 3개 이상일 때 서사감이 생김.
- **최종 결과물**: 챕터가 이어지는 "나의 이야기" 통합 리포트(공유 카드는 장별 요약을 이어 붙인 형태).
- **재방문 구조**: "3장 중 1장만 채워졌어요" 식 진행률 표시.
- **장점**: 문화 왜곡 위험이 가장 낮고, 10분 이상 분량 목표(4장)와 자연스럽게 연결된다.
- **단점**: 수치화된 "공식"이라는 느낌이 약해 마케팅 카피 상 임팩트가 A·B보다 덜할 수 있다.

**비교 결론**: 안 A는 문화적 정확성 리스크가 가장 크고, 안 B와 안 C는 리스크가 낮다. 안 C가 콘텐츠 깊이 목표(4장 참고)와 가장 잘 맞는다.

### 2.1 중요한 제약 — 방 간 결과를 어디에 보관할 것인가

CLAUDE.md 6장은 "입력값(생년월일·이름 등)"을 fetch·localStorage·쿠키·URL 파라미터에 절대 넣지 말라고 한다. 통합 공식을 만들려면 방마다 나온 **결과 유형 코드**(입력값이 아니라 계산 결과, 예: "오검=자작나무", "나크샤트라=아슈위니")를 다음 방으로 옮겨야 하는데, 방식별로 다음과 같은 차이가 있다.

| 방식 | 설명 | CLAUDE.md 6장과의 관계 |
|---|---|---|
| ① localStorage/sessionStorage에 결과 코드만 저장 | 예: `{rune:"F-U-Th", star:"Ashwini"}` | 규칙 문구상 금지 대상은 "입력값"이며 결과 코드는 입력값이 아니므로 **문자 그대로는 위반이 아닐 수 있음**. 다만 "기기에 남기지 않는다"는 규칙의 취지와는 긴장 관계가 있어 해석이 갈림 |
| ② URL 파라미터로 결과 코드 전달 | 예: `?r=F-U-Th&s=05` | 규칙이 "URL 파라미터"를 명시적으로 금지 대상에 포함하고 있어 ①보다 더 위반 소지가 큼. 게다가 URL은 캡처·전달이 쉬워 타인에게 결과 코드가 노출될 위험도 있음 |
| ③ 사용자가 결과 코드를 직접 옮기기(자동 저장 없음) | 각 방 결과 화면에 짧은 코드를 보여주고, "공식의 방"에서 사용자가 그 코드를 직접 입력 | 저장을 아예 하지 않으므로 규칙 위반 소지가 없음. 단, 코드를 여러 개 기억·받아적어야 해 이탈 위험이 큼 |
| ④ 공유 카드 재활용 | share-card.js로 만든 결과 카드 이미지/텍스트 안에 결과 코드를 포함시키고, 사용자가 그 카드(사진첩·카톡)를 "공식의 방"에 다시 가져와 코드를 입력 | 저장 매체가 브라우저 저장소·URL이 아니라 사용자의 사진첩이므로 6장의 어떤 조항과도 충돌하지 않음. 기존 부품(share-card.js) 재사용 가능. 코드 입력의 번거로움은 UX 설계(간단한 4자리 코드 등)로 완화 필요 — 구체 설계는 designer 몫 |

**운영자 결정 필요**: 위 4방식 중 어느 것을 쓸지, 그리고 ①을 "입력값이 아니므로 허용"으로 해석할지 "취지 위반이므로 금지"로 해석할지 CLAUDE.md 1장(개인정보 보호가 최우선)에 비추어 운영자가 직접 판단해야 한다. planner는 여기서 규칙을 새로 해석해 확정할 권한이 없다.

## 3. 비즈니스 모델 검토

### 3.1 광고 배치 (CLAUDE.md 7장 준수: 한 화면 최대 2개, 결과 문구 바로 위아래·버튼 옆 금지)

- 결과를 여러 장(챕터)으로 나누는 구조(4장 참고)를 활용해, **챕터와 챕터 "사이"**에만 광고 슬롯을 둔다(챕터 본문 안에는 넣지 않음). 예: 4장 구성이면 2장 뒤·최종 챕터(면책 문구) 뒤 총 2곳.
- **애매한 점**: "한 화면"이 뷰포트를 뜻하는지, 스크롤이 이어지는 결과 페이지 전체를 뜻하는지 CLAUDE.md에 명시돼 있지 않다. 결과 페이지가 길게 이어지는 단일 스크롤이라면 페이지 전체 기준 최대 2개로 해석하는 편이 안전하다고 보이나, 이는 qa-reviewer·designer와 함께 확정할 사항으로 남긴다.
- 의식(ritual) 연출 화면, 통합 공식의 최종 카드 화면에는 광고를 넣지 않는다(기존 spec의 원칙 유지).

### 3.2 제휴(쿠팡 파트너스)

억지스럽지 않은 카테고리 후보:
- 룬·마야·켈트·이집트 관련 **도서**(신화·역사 교양서)
- 의식(ritual) 분위기와 맞는 **인센스·무드등·다이어리**류
- 수능 시즌(시빌라 신탁)에는 "합격 기원 선물"(초콜릿, 손편지지, 스터디 플래너) 정도로 제한 — 건강·성적 예측과 얽히는 상품(영양제 등)은 CLAUDE.md 8장(건강 예측 금지)과 얽힐 수 있어 배제.
- affiliate.js가 이미 대가성 문구 자동 삽입을 처리하므로 기술적 추가 작업은 적음.

### 3.3 유료 콘텐츠 — 선택지 비교 (추천안 1개)

CLAUDE.md 7장과 agents/planner.md는 현재 "자체 결제·후원·유료 결과 기능"을 금지한다. 운영자가 유료 범위를 묻고 있으므로, 이 규칙을 전제하지 않고 선택지를 비교한다.

**선택지 1 — 완전 무료(현행 유지)**
- 규칙 변경: 없음. 법적/운영 요건: 없음. 정적 웹 원칙과 충돌: 없음.
- 수익은 광고+제휴로 한정, 상한이 낮음.

**선택지 2 — 무료 + 유료 심화 리포트**
- 필요한 규칙 변경: CLAUDE.md 7장의 "자체 결제·후원·유료 결과 기능은 만들지 않는다" 문구, agents/planner.md의 동일 금지 문구를 모두 고쳐야 함.
- 법적·운영 요건: 전자상거래법상 통신판매업 신고 필요 여부 **미확인**(디지털 콘텐츠 판매도 신고 대상인 경우가 많다고 알려져 있으나 정확한 기준은 미확인), 결제대행(PG)·카카오페이 등 연동 필요, 청약철회·환불 고지 필요(디지털 콘텐츠의 "열람 즉시 청약철회 제한" 조건 등 정확한 법적 요건 **미확인**), 결제자 개인정보(카드정보 등) 처리방침 필요.
- 정적 웹·서버 없음 원칙과의 충돌: **정면 충돌**. 순수 HTML+CSS+JS로는 결제를 안전하게 처리할 수 없고 최소한 PG사 스크립트·서버리스 결제 승인 로직이 필요해, "1인 운영 앱 공장, 정적 사이트 대량생산" 정체성과 근본적으로 맞지 않는다.

**선택지 3 — 무료 + 보상형 광고로 심화 콘텐츠 언락**
- 결제가 아니므로 규칙 변경 폭은 작지만, "광고를 눌러/봐 주세요" 류 유도 문구 금지(7장)와 긴장 관계가 있다.
- 애드센스·애드핏이 보상형(리워드) 광고 상품을 실제로 지원하는지 **미확인** — 선행 조사 필요.

**추천안**: **선택지 1(완전 무료) + 3.2의 제휴 확장**을 추천한다. 선택지 2는 앱 공장의 "정적 웹·서버 없음, 1인 운영, 빠른 대량 출시" 정체성과 근본적으로 충돌하므로, 정말 하려면 이 제품군과 완전히 다른 별도 프로젝트(서버·결제 스택 보유)로 분리해야 한다는 점을 운영자에게 명확히 알린다.

## 4. 콘텐츠 깊이 설계

### 4.1 "사건 위주 서술" 구조화

결과 하나를 여러 **장(章)**으로 나눈다. 예시(오검의 방 기준):
1. **1장 뿌리** — 태어난 계절의 나무, 그 나무의 문화 이야기
2. **2장 그 나무 아래 있었던 일** — 구체적 일상 장면 + 과거 회상형 서술("완전 내 얘기" 포인트)
3. **3장 그림자** — 그 성향의 이면
4. **4장 다음 계절** — 실행 가능한 긍정적 조언

**예시 문장(사건 위주, 규칙 준수 — 죽음·사고·건강 예언 없음, 정확도 과장 없음)**
- "작년 이맘때, 별다른 이유 없이 오래된 사진첩을 꺼내 본 적 있지 않나요? 자작나무의 계절은 그렇게, 이유 없이 과거를 그리워하게 만들어요."
- "회의실 문을 열기 직전, 아무도 안 볼 때 숨을 한번 크게 고르는 버릇. 그 짧은 순간에 당신의 가시가 돋아나요."
- "누군가 무심코 던진 한마디가 사흘째 머릿속에서 재생되고 있다면, 그건 우연이 아니에요."

### 4.2 분량 추정 (가정 명시)

- 한국어 묵독 속도의 공인된 국내 표준치는 **미확인**. 이 제안서는 모바일 화면(스크롤·삽화 감상 시간 포함)을 가정해 **분당 400~500자**로 가정한다(근거 없는 가정). 이 가정에 따르면 10분 목표 = **약 4,000~5,000자**.
- data.js를 읽어 확인한 결과, 현재 룬 결과 1회 분량(룬 3장 서술 + 이름 표기 + 상식 한 줄)은 대략 **600~1,000자 수준**으로 추정된다. 10분 목표에 도달하려면 방 하나당 **현재의 약 4~5배** 분량 확장이 필요하다는 뜻이다.
- 방 하나당 목표: 약 4,000~5,000자. 통합 결과(안 C 채택 시 여러 장을 잇는 서사)는 별도로 약 1,500~2,500자 추가.

### 4.3 CLAUDE.md 8장 준수하며 "소름 돋는" 느낌 만들기

- 금지: "100% 적중"류 정확도 과장, 죽음·사고·건강 예언, 마지막은 반드시 긍정적 조언.
- 대신 쓸 장치: **구체적 일상 장면**(회의실 문 앞, 사진첩, 카톡 답장 대기 등 누구나 겪는 순간을 정확히 묘사), **과거 회상형 서술**("작년 이맘때~", "어릴 때 한 번쯤~")로 예언이 아니라 "알아맞힘"의 착각을 준다, **반전 정보**(기존 spec의 서양-베다 별자리 반전처럼 문화적 사실을 이용한 반전).

### 4.4 이탈 방지 UX 방향 (방향만, 구체 설계는 designer 몫)

- 결과 페이지 진입 시 "예상 소요 시간 약 10분"을 미리 알려 기대치를 설정한다(짧을 거라 기대했다가 이탈하는 상황을 방지).
- 챕터 전환마다 짧은 후킹 문장으로 다음 장에 대한 기대감을 만든다(클리프행어식).
- 챕터마다 시각적 리듬 변화(배경·삽화 전환)로 스크롤 피로를 줄인다.
- 광고는 챕터 "사이"에만 두어 챕터 내부 몰입을 깨지 않는다.
- 진행률 표시(예: "2/4장")로 남은 분량을 가늠하게 한다.

## 5. 성공 기준 제안

근거가 있는 수치는 없다(앱 공장 첫 확장이라 비교 기준 없음). 모두 "제안값(근거 없음)"으로 표시한다.

| 지표 | 제안값(근거 없음) |
|---|---|
| 결과 도달률(시작→결과 완료) | 60% 이상 |
| 의식(ritual) 완료율 | 50% 이상 |
| 공유 클릭률 | 8~12% |
| 결과 페이지 평균 체류시간 | 4~5분 이상(전체 10분 완독은 소수만 기대) |
| 다른 방 이동률 | 20% 이상 |
| "통합 공식" 완료율(6개 방을 다 도는 비율) | 5~10%(깔때기가 길어 낮게 설정) |
| 검색 키워드 유입 순위/유입량 | **미확인** — 정량 검색량 조사가 선행되지 않아 목표 수치를 잡을 수 없음 |

## 6. 운영자가 결정할 것

1. **방 후보 최종 확정** — 추천안: 기존 룬·베다 유지 + 신규 4개(켈트 오검 → 로마 시빌라 신탁 → 마야 촐킨 → 이집트 데칸) 순서로 확정.
2. **통합 공식 방향** — 추천안: **안 C(시간 흐름/인생 서사 통합)**. 안 A(원소 매핑)는 문화 왜곡 우려로 비추천.
3. **방 간 결과 코드 보관 방식** — 추천안: **방식 ④(공유 카드에 코드 포함, 사용자가 직접 옮김, 저장소 미사용)**. 방식 ①(localStorage)을 쓸지는 CLAUDE.md 6장의 "입력값" 문구를 좁게 해석할지 넓게 해석할지에 대한 운영자 판단이 필요.
4. **유료 콘텐츠 도입 여부** — 추천안: **선택지 1(완전 무료) + 제휴 확장**. 유료 심화 리포트(선택지 2)는 정적 웹·1인 운영 원칙과 충돌해 비추천.
5. **광고 "한 화면"의 기준** — 뷰포트 단위인지 결과 페이지 전체 단위인지 확정 필요(qa-reviewer·designer와 협의).
6. **보상형 광고 도입 여부** — 애드센스/애드핏의 실제 지원 정책이 미확인이라 선행 조사 필요.
7. **검색 키워드 정량 조사** — 이 제안서의 검색 수요 점수는 WebSearch 정성 조사(블로그·앱 존재 여부)에 근거했을 뿐, 네이버 검색광고 키워드도구 등을 통한 정량 검색량은 대부분 미확인이다. 출시 전 조사 필요.
8. **성공 기준 수치 확정** — 5장의 모든 수치는 "제안값(근거 없음)"이므로 승인 또는 수정 필요.
9. **출시 순서·시즌 타이밍 확정** — 오검(할로윈 10/31), 시빌라(수능 11/19) 목표 역산 시 개발 착수 시점을 언제로 할지 확정 필요.
