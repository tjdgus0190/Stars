# 제안서: 낯선 점술관 다듬기 (기획자 점검)

- 작성: planner, 2026-09-30. 운영자 선택 전 단계다. 고르신 항목만 기획서(specs/strange-oracle.md)에 결정으로 옮긴다.
- 점검 대상: 결정 53 재검수 통과 시점의 실제 파일(index.html, data.js, app.js, common/, og-image.png).
- 전제: 결정 54(AI 이미지)는 보류 상태. 아래 제안은 모두 CSS·SVG·기존 문구만으로 가능하다. 새 AI 이미지·영상·유료 자산은 쓰지 않는다.
- 브라우저로 직접 돌려 보지는 않았다. 파일과 QA 보고서로 확인한 것만 근거로 적었고, 확인 못 한 것은 "미확인"으로 표시했다.

## 요약: 가장 값진 세 가지

1. **공유해도 친구가 들어올 길이 없다 (항목 1).** 공유는 이미지와 글만 나가고 주소가 없다. 공유 미리보기 그림(og-image)은 두 방 시절 문구 그대로다.
2. **잘되는지 잴 수단도, 광고를 채울 부품도 없다 (항목 2).** analytics.js·ads.js가 아예 없어 성공 기준(결과 도달률·공유 클릭률)을 하나도 잴 수 없고, 광고 자리는 빈 칸이다.
3. **완주까지 약 14분인데 탭을 닫으면 전부 사라진다 (항목 3).** 결제는 6/6 뒤에만 가능하므로, 중간 이탈은 곧 매출 0이다. 입구는 전체 시간을 알려 주지 않는다.

## 항목

### 1. 공유 고리가 끊겨 있다
- **무엇이 아쉬운가(근거)**
  - 공유는 이미지 파일과 글만 보낸다. 주소가 없다: `common/share-card.js:774` `navigator.share({ files: [file], text })`.
  - 공유 글에도 주소가 없다: data.js `*.card.shareText` (예: "바이킹의 룬으로 본 나의 운명").
  - 카드 맨 아래는 "낯선 점술관" 이름뿐이다: data.js:797 `card.footer`. 주석에 "서비스 주소는 배포 뒤 덧붙인다"고 남아 있다.
  - 링크 복사·카카오 공유 부품(share-buttons.js)이 없다: `common/`에는 base.css, disclaimer.js, share-card.js 세 개뿐이고 docs/common.md:11에 "아직 없음"으로 적혀 있다.
  - og-image.png 문구가 "바이킹의 룬 · 인도의 베다 점성술로 읽는 나의 운명"이다. 여섯 방·"나의 이야기" 이전 그림이다(9/24 파일).
  - `og:image`가 상대 경로(index.html:12)이고 `og:url`·canonical이 없다. 카카오톡 미리보기가 제대로 뜨는지는 미확인.
- **제안**
  - (a) 링크 복사 버튼을 공유 버튼 옆 글자 링크로 추가한다. common/share-buttons.js를 새로 만들되 우선 링크 복사만 넣는다. 카카오 공유는 운영자 키가 필요하므로 뒤로 미룬다.
  - (b) 공유 글 끝과 카드 맨 아래에 서비스 주소를 넣는다. 주소는 운영자가 정한다.
  - (c) og-image를 여섯 문 상징(기존 SVG)으로 다시 만들고, og:url과 절대 경로를 넣는다.
- **기대 효과**: 셀링 포인트 2번("너는 몇 장까지 채웠어?")이 실제로 유입으로 이어진다. 지금은 공유가 일어나도 유입이 0이다.
- **작업량**: 소~중. developer(부품·메타), designer(og-image), copywriter(공유 글).
- **위험·규칙 확인**: 주소에 입력값·결과를 넣지 않는다(6장). 공통 부품을 새로 만들면 docs/common.md에 사용법을 적는다(5장). 배포 주소가 정해져야 끝낼 수 있다.

### 2. 측정과 광고 부품이 없다
- **무엇이 아쉬운가(근거)**
  - index.html이 불러오는 공통 스크립트는 share-card.js와 disclaimer.js 둘뿐이다(index.html:2728~2729).
  - app.js에 분석 호출도 광고 채우기도 없다. `analytics`, `ads.js`, `ad-slot`을 찾았으나 0건이다.
  - 광고 자리 9곳(`data-ad="hub"`, `result-end` ×6, `story-end` 등)은 빈 칸으로만 있다. QA의 "입구 광고 1개"는 빈 칸 개수를 센 것이다.
  - 기획서 성공 기준(결과 도달률 60%, 공유 클릭률 8~12%, 나의 이야기 도달률 15%)을 잴 방법이 없다. "기준 미달 시 재검토" 판단도 할 수 없다.
- **제안**
  - common/analytics.js를 최소로 만든다. 이벤트는 방문, 방별 결과 도달(방 이름), 6/6 도달, 공유 클릭, 책 미리보기 열람, 결제 버튼 클릭까지만.
  - common/ads.js를 만들어 7장 규칙(화면당 최대 2개, 금지 위치)을 코드로 막는다.
- **기대 효과**: 어느 방에서 빠지는지 보인다. 항목 3·4 같은 다듬기의 효과를 숫자로 판단할 수 있다.
- **작업량**: 중. developer. 이후 qa-reviewer가 개인정보 재검수.
- **위험·규칙 확인 (운영자 판단 필요)**
  - 애드센스·애드핏·분석 도구의 공식 스크립트는 자기 회사 주소에서 불러와야 한다. CLAUDE.md 3장은 외부 라이브러리를 cdnjs·jsdelivr로만 제한하고, 예외는 결제 SDK뿐이다. **광고·분석 공식 스크립트에도 예외를 둘지 운영자가 정해야 한다.**
  - 어떤 분석 도구를 쓸지(계정 필요)도 운영자 몫이다.
  - 분석 이벤트에 결과 유형 코드를 어디까지 넣을지 정해야 한다. 데칸·촐킨·달의 집 코드를 함께 보내면 생일을 좁힐 수 있다. 방 이름과 원형 코드까지만 보내기를 권한다.
  - QA의 "외부 요청은 jsdelivr뿐" 검사 기준도 함께 바뀐다.

### 3. 완주 부담과 세션 소실
- **무엇이 아쉬운가(근거)**
  - 무료 읽기만 여섯 방 합계 약 6,850자, 약 14분이다(tests.md:305~309). 입력·의식 시간은 미확인이다(QA 8단계 "확인하지 못한 것").
  - 입구 칩은 "방마다 2~3분 남짓"만 말한다(data.js:234). 전체가 얼마나 걸리는지, 중간에 멈춰도 되는지는 안 알려 준다.
  - 진행은 sessionStorage에만 있다(app.js:98~135). 탭이 닫히거나 인앱 브라우저가 정리되면 전부 사라진다.
  - 새 세션은 주소와 상관없이 입구·Ⅰ번 방부터 시작한다(app.js:3419~3428). 다시 온 사람은 여섯 방을 처음부터 돌아야 한다.
  - 결제는 6/6 뒤에만 가능하다(결정 44). 중간 이탈자는 유료 대상이 되지 못한다.
  - 유일한 반복 요소인 시빌라 "다른 신탁 받기"(data.js:705)가 Ⅵ번 방이라, 재방문자에게 가장 멀다.
- **제안**
  - (a) 입구 칩·안내에 전체 시간과 "방 하나만 봐도 한 장은 완결"을 밝힌다. 문구만 고친다. 권장.
  - (b) 선택안, 운영자 판단: "이어가기 코드". 방 결과 코드만 담은 짧은 코드를 사용자가 직접 복사해 두었다가 입구에 넣으면 진행이 복원된다. 영수증 코드가 이미 같은 방식으로 결과 코드 12자를 담는다(paycode.js). 이름·생일은 담지 않으므로 복원 뒤 이름은 "당신"으로 나온다.
  - (c) 3/6 지점에서 "절반 왔어요" 한 줄과 공유 유도를 입구 "지금까지의 이야기"에 넣는다. 새 화면은 만들지 않는다.
- **기대 효과**: 기대치를 미리 맞춰 중간 이탈을 줄이고, 재방문을 가능하게 한다.
- **작업량**: (a)(c) 소, copywriter + developer. (b) 중, developer + designer.
- **위험·규칙 확인**
  - (b)는 저장·전송이 없어 6장 위반은 아니라고 본다. 다만 코드에서 데칸·촐킨·달의 집을 거꾸로 짚으면 생일 범위가 좁혀진다. "남에게 보여 주지 마세요" 안내가 필요하고, 하려면 운영자 승인이 필요하다.
  - localStorage에 진행을 저장하는 안은 제안하지 않는다(6장).

### 4. 유료 직전 화면이 책을 보여 주지 않는다
- **무엇이 아쉬운가(근거)**
  - 결정 53으로 책은 "낡은 책을 넘기는" 경험이 됐지만, 결제 전 미리보기(#screen-deeper, index.html:2204~)는 봉인 줄이 그어진 목차와 글 견본뿐이다. 가장 큰 매력인 책의 모습이 결제 전에 안 보인다.
  - 문구가 옛 구조 그대로다: data.js:826 `deeper.lead`가 "한 화면에 순서대로 엮어요"라고 한다. 지금은 쪽을 넘기는 책이다.
  - 분량을 "약 N자"로만 알린다(data.js:919). QA 실측은 360×800에서 113쪽이다.
  - 같은 상품을 네 가지 이름으로 부른다:

    | 부르는 이름 | 쓰인 곳 |
    |---|---|
    | 한 권의 책 | data.js:246 `hub.book` |
    | 더 깊은 이야기 / DEEPER STORY | data.js:773~774 `story.paid`, :1048 `keepsake.eyebrow` |
    | 리포트 | data.js:789, :889, :924, :972 |
    | 소장판 | data.js:992 |

    나의 이야기 화면의 유료 카드는 "더 깊은 이야기", 입구는 "한 권의 책"이라 서로 다른 상품처럼 보인다.
- **제안**
  - (a) 이름을 "한 권의 책"으로 통일한다(copywriter).
  - (b) 미리보기 맨 위에 책 종이 모양(기존 리더 CSS 재사용)으로 두 쪽을 보여 준다. 내 원형 이름이 찍힌 표지 한 쪽과, 기존 무료 견본 문단(`deeper.sample.body`)을 담은 견본 한 쪽이다. 유료 문장은 쓰지 않는다.
  - (c) 분량에 "읽는 데 약 N분"을 같이 적는다. 쪽 수는 화면 크기에 따라 달라지므로(640 높이에서 157쪽) 숫자로 못 박지 않는다.
- **기대 효과**: 결제 직전에 "무엇을 받는지"가 눈으로 보인다. 7장의 결제 전 고지도 더 분명해진다.
- **작업량**: (a)(c) 소, copywriter + developer. (b) 중, designer + developer.
- **위험·규칙 확인**
  - 견본은 지금처럼 "가상의 두 사람"임을 밝힌다.
  - 분량·시간은 실측 자동 계산값만 쓴다(과장 금지).
  - 공개 파일에 유료 문구 0건을 유지한다(build-dist 검사).
  - 결제 꺼짐 상태에서는 지금처럼 보이지 않는다.

### 5. 검색으로 온 사람과 강제 순서가 어긋난다
- **무엇이 아쉬운가(근거)**
  - meta.json 키워드는 "룬 점, 나크샤트라, 마야 촐킨…"이다. 그런데 룬은 Ⅴ번째 방이고, 딥링크(#rune)는 입구로 돌려보낸다(app.js:3419, 결정 37). "룬 점"으로 들어온 사람은 네 방을 지나야 룬을 본다.
  - 검색에 읽히는 글이 한 주소의 FAQ 341~389자뿐이다(QA 기록). 각 문화 소개(`*.intro.lore`)와 상식 카드는 JS가 채워서, JS 실행 전 HTML에는 없다.
  - `<title>`의 방 순서(룬·베다·오검…)가 실제 순서(오검·별·데칸·촐킨·룬·시빌라)와 다르다(index.html:7).
  - 프로모션 페이지(promo/)는 아직 없다(1-D 미착수).
- **제안**
  - (a) title·description의 방 순서를 실제 순서로 맞춘다. 소.
  - (b) 선택안: 문화 안내 정적 페이지 6장을 만든다(예: guide/rune.html). 기존 lore·상식 문구만 재사용하고, 끝에 "입구에서 시작하기" 버튼을 둔다. 강제 순서(결정 37)는 건드리지 않는다.
- **기대 효과**: 검색 의도("룬 문자가 뭐지")를 채워 주고 입구로 보낸다. 광고 심사용 글 분량도 늘어난다. 실제 검색량은 미확인(기획서의 키워드 조사도 미확인).
- **작업량**: (a) 소, developer. (b) 중, designer 틀 1개 + developer + copywriter 검토.
- **위험·규칙 확인**
  - 새 고증 주장을 더하지 않는다. CREDITS.md에 미확인으로 남은 항목(오검 나무, 촐킨 키체 이름)은 싣지 않는다.
  - 안내 페이지 문구도 data 파일에 모은다(3장).
  - 범위 밖 기능이므로 운영자 선택 사항이다.

### 6. 입구 첫 3초: 무엇을 받는지와 "무료"가 안 보인다
- **무엇이 아쉬운가(근거)**
  - 제목 아래 요약이 추상적이다: "여러 문화의 점을 하나로 엮어, 당신이라는 사람을 한 편의 이야기로 그려요"(data.js:105).
  - 셀링 문서의 첫 3초 1순위 "사주도 타로도 아닌, 처음 듣는 이야기"는 `hub.lead`에 있으나 화면에서 쓰지 않는다(data.js:226 주석 "더 쓰지 않는다").
  - "무료"라는 말이 첫 화면에 없다. FAQ 다섯째 답에만 있다.
  - 무엇을 넣어야 하는지(이름·생일)는 안 알려 주는데, 개인정보 안내(`intro.note`)가 먼저 나온다.
  - 영문 윗줄 "WORLD ORACLE HALL"은 정보가 없다.
- **제안**: copywriter가 요약 한 줄을 "낯섦 + 받는 것"으로 다시 쓴다. 칩 셋 중 하나를 "여섯 방 모두 무료"로, 개인정보 줄을 "이름과 생일만 넣어요 · 이 탭 밖으로 나가지 않아요" 식으로 합친다. 요소 수는 늘리지 않는다(결정 52 "깔끔하게" 유지).
- **기대 효과**: "이게 뭔데, 돈 드나, 뭘 넣어야 하나"가 스크롤 없이 풀린다.
- **작업량**: 소. copywriter. 길이 제한은 designer가 확인한다.
- **위험·규칙 확인**
  - "무료"라고 쓸 때 유료 책이 따로 있다는 사실과 충돌하지 않게 "여섯 방"으로 한정한다.
  - 정확도 과장 표현은 쓰지 않는다(8장).

### 7. 남은 찌꺼기 정리
- **무엇이 아쉬운가(근거)**
  - 미사용 AI 시안이 제품 폴더에 있다: `products/strange-oracle/assets/ai/` 14개 파일, 14MB, 원본 PNG 포함. index.html·style.css·app.js에서 참조 0건이다. 배포 폴더에 딸려 가는지는 미확인(tools/build-dist.js의 제외 목록을 확인하지 못했다). CREDITS.md에는 이미 결정 54 항목이 적혀 있다.
  - data.js에 더 쓰지 않는 문구가 남아 있다. "코드를 몰라도 문구를 고친다"는 목적에 방해가 된다.
