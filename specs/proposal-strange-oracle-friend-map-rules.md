## 1. 기능 요약 (결정 84)

일곱 방을 모두 마친 사람은 **자기만의 지도 링크**를 만들어 친구에게 보낸다. 그 링크로 들어온 친구가 일곱 방을 마치면, 친구의 동의를 받은 뒤 **자동으로 내 지도에 모인다**. 친구는 나와의 궁합 점수를 바로 짧게 본다. 지도는 **오각형**이다. 가운데에 내가 있고, 궁합이 좋은 친구는 가까이, 먼 친구는 멀리 놓이며, 친구는 **별명과 아이콘**으로 표시된다. 아이콘을 누르면 **궁합 점수 상세와 어떤 관계인지 짧은 요약**이 나오고, 지도 아래에는 **궁합 순위**가 있다. 판독 기준은 결제 없이 일곱 방을 마치면 나오는 성향(원형)이다. 지도 만들기·참여·보기는 **무료**이고 운영 비용 0(무료 한도 안)이 목표다. **상세 궁합 풀이는 전체 리포트(책)를 결제한 뒤** 볼 수 있다.

> 참고: 지금 배포판은 `pay.mode = "off"`(결정 94)라 책이 화면에 없다. 지도의 "상세"는 결제를 live로 켜기 전까지 배포판에서 보이지 않는다. 무료 부분(점수·순위·한 줄 관계)만으로 지도가 완결되도록 15단계에서 설계한다.

## 2. 서버에 저장하는 것 — 최소안

### 2-1. 구조 한눈에
- 서버는 **기록을 맡아 두는 일만** 한다. 궁합 점수, 지도 위 위치, 순위, 관계 문장은 모두 **지도 주인의 브라우저**가 공개 표(data.js 계열)로 계산한다.
- 지도 하나에 무작위 값 두 개를 만든다.
  - **초대 ID**: 친구에게 보내는 링크에 들어간다. 이 값으로는 **친구 더하기**와 "지도 주인 별명·아이콘·원형 보기"만 된다. 지도(친구 목록)는 볼 수 없다.
  - **열람 키**: 지도 주인만 갖는다. 이 값이 있어야 친구 목록을 볼 수 있고 지울 수 있다. 서버에는 **해시만** 둔다. 요청할 때 주소(URL)에 넣지 않고 요청 본문으로 보낸다(접속 기록에 남지 않게).
- 친구는 참여할 때 **삭제 코드**(무작위)를 한 번 받는다. 서버에는 해시만 둔다.

### 2-2. 저장하는 칸

| 묶음 | 칸 | 내용·형식 | 왜 필요한가 |
|---|---|---|---|
| 지도 | 초대 ID | 무작위 128비트, 영숫자 | 친구 링크 |
| 지도 | 열람 키 해시 | SHA-256 해시 | 주인 확인. 원문은 서버에 없음 |
| 지도 | 주인 별명 | 사용자가 새로 적은 1~8자 | 친구 화면 "○○의 지도" |
| 지도 | 주인 아이콘 | 정해 둔 아이콘 목록의 코드(예: `i07`) | 지도 가운데 표시 |
| 지도 | 주인 원형 코드 | 2-4에서 고른 범위(추천: 주·보조 원형) | 친구가 바로 점수를 보려면 필요 |
| 지도 | 초대 열림 여부 | 참/거짓 | 주인이 초대를 닫을 수 있게 |
| 지도 | 만든 날, 마지막 활동 날 | 날짜(일 단위) | 자동 삭제 계산 |
| 친구 | 기록 ID | 무작위 | 개별 삭제 |
| 친구 | 별명 | 사용자가 새로 적은 1~8자 | 지도 표시 |
| 친구 | 아이콘 | 아이콘 코드 | 지도 표시 |
| 친구 | 원형 코드 | 지도와 같은 범위 | 점수 계산 |
| 친구 | 삭제 코드 해시 | SHA-256 해시 | 친구 본인 삭제 |
| 친구 | 참여 날 | 날짜(일 단위) | 순서·자동 삭제 |

- 한 지도에 친구는 **최대 30명**[planner 기본값, 15단계에서 화면에 맞춰 조정]. 넘으면 초대가 자동으로 닫힌다.
- "어떤 관계인지"(연인·친구·동료·가족 4유형) 선택은 **저장하지 않는다**[기본값]. 관계 요약은 두 원형 쌍에서 나오는 문장으로 보인다. 저장하면 정보가 하나 늘기 때문이다.

### 2-3. 저장하지 않는 것 (어떤 경우에도)
- **이름 원문**(만신의 방 입력값). 별명 칸을 이름으로 **미리 채우지도 않는다**.
- **생년월일, 태어난 시각, 성별**
- **이어가기 코드(SOG…), 열람 코드(SOP…)**, 결제 정보
- **방별 세부 번호**: 사주 일주·일간, 오검, 나크샤트라, 데칸, 촐킨, 룬 세 돌, 신탁 번호
- 시빌라 질문 글·주제
- IP 주소, 기기 정보(User-Agent), 쿠키. (남용 막기용 횟수 제한은 2-6 참조: 서비스 기본 기능을 쓰고, 우리 저장소에 IP를 쌓지 않는다.)
- 위치, 연락처, 프로필 사진(아이콘은 정해 둔 그림 중에서만 고른다. 사진 올리기 없음)

### 2-4. 결과 코드로 생일을 거꾸로 알아낼 위험 (기존 35·36번 논의)
36번에서 정리한 대로, 데칸·촐킨·나크샤트라 번호를 합치면 **태어난 날을 알아낼 수 있다**. 만신의 방의 일주(60갑자)까지 더하면 더 좁아진다. 지도는 **아는 사람끼리** 쓰므로, 별명만 있어도 누구인지 바로 안다. 그래서 세부 번호가 서버에 가면 "누구의 생일"이 그대로 남는 것과 같다.

| 안 | 저장하는 코드 | 경우의 수 | 생일 역추적 위험 | 궁합 표현력 | 판단 |
|---|---|---|---|---|---|
| A | 주 원형 1개 | 8 | 거의 없음. 원형은 일곱 방 태그의 합산이고 룬(무작위)·시빌라(질문 선택)도 섞여 생일만의 함수가 아니다 | 낮음. 같은 원형 친구는 모두 같은 점수 → 지도에서 겹침 | 가능 |
| **B** | **주 원형 + 보조 원형(합산 2위)** | **8×7 = 56** | 거의 없음(A와 같은 이유. 정보량만 조금 늘어남) | 중간. 같은 주 원형이어도 보조 원형으로 점수가 갈린다 | **추천** |
| C | 방별 원형 태그 7개 | 8⁷ | 중간. 방마다 세부 번호가 태그 하나로 묶이는 정도라, 여러 방을 겹치면 생일 범위가 좁아질 수 있다(직접 계산해 보지는 않은 추산) | 높음 | 비추천 |
| D | 방별 세부 번호 | 매우 많음 | **높음**(36번 그대로) | 가장 높음(방별 관계 등급까지) | **금지** |

- 추천은 **B**다. 지도의 "가깝다·멀다"를 갈라 보이기에 충분하고, 생일과는 사실상 끊겨 있다.
- 대가: 책 3장(궁합)의 **방별 관계 등급**(오검·데칸·촐킨)은 세부 번호가 있어야 나오므로 지도의 상세에는 쓰지 않는다. 지도 상세는 **원형 쌍 궁합 문장**(36쌍)으로 만든다. 점수 공식(주·보조 원형 → 0~100)은 15단계에서 정한다.
- 보조 원형이 동점일 때 정하는 규칙(기존 "더 앞선 장" 규칙)은 브라우저에서 결정해 코드만 보낸다.

### 2-5. 별명, 보관 기간, 삭제, 링크가 샐 때
**별명**
- 실명 대신 별명을 쓰게 한다. 칸 안내: "친구가 알아볼 별명(실명 말고)". 1~8자, 비워 두면 보낼 수 없다.
- 이름 입력값으로 미리 채우지 않는다. 브라우저가 "이름 입력값과 같은 별명"이면 한 번 더 묻는다("실명 그대로 보낼까요?") — 막지는 않는다[기본값].
- 전화번호 모양(숫자 7자 이상), 주소(`http`, `@`), 금칙어는 서버와 브라우저 둘 다에서 거른다.

**보관 기간** [추천, 질문 4]
- 지도는 **마지막 활동(친구 참여·주인 열람) 뒤 90일**이 지나면 친구 기록과 함께 자동 삭제한다. 만든 날로부터 **최대 1년**이면 활동이 있어도 지운다.
- 저장소의 만료(TTL) 기능이나 하루 한 번 정리 작업으로 지운다.

**삭제 방법**
- 지도 주인: (1) 친구 한 명 지우기, (2) 지도 전체 지우기, (3) 초대 닫기·다시 열기, (4) 열람 키 바꾸기. 모두 즉시 반영.
- 친구 본인: 참여 직후 보여 주는 **삭제 코드**로 언제든 자기 기록을 지운다(코드는 이 탭 sessionStorage에도 잠시 둠, 기존 "내 정보 지우기"를 누르면 서버 기록 삭제도 함께 제안). 코드를 잃으면 지도 주인에게 지워 달라고 하라는 안내와 운영자 문의처(법적 고지의 문의 이메일)를 적는다.
- 지운 기록은 백업에도 남지 않게 한다(무료 요금제는 자동 백업이 없거나 짧다. 서비스별 보존 기간은 미확인).

**지도 링크(초대 ID)가 새면**
- 아무나 그 지도에 친구로 끼어들 수 있다(가짜 별명 등록). 주인 별명·아이콘·원형은 보인다.
- **지도(친구 목록)는 보이지 않는다** — 열람 키가 따로 있기 때문.
- 대응: 주인이 가짜 기록을 지우고 초대를 닫거나, 새 초대 ID로 바꾼다(옛 링크는 무효).

**열람 키가 새면**
- 친구들의 별명·아이콘·원형 코드가 보인다(생일·실명은 애초에 없음).
- 대응: 주인이 "열람 키 바꾸기"를 누르면 옛 키는 즉시 무효. 동의 화면에 "지도 주인이 지도를 보여 주면 다른 사람도 볼 수 있다"를 적는다.

### 2-6. 남용 막기 (스팸 등록, 지도 긁어 가기)
| 위험 | 막는 법 |
|---|---|
| 한 지도에 가짜 친구 대량 등록 | 지도당 30명 상한, 초대 닫기, 같은 탭에서 한 지도에 한 번만(sessionStorage 표시), 서버 쪽 지도당 시간당 참여 상한(예: 10회) |
| 지도 대량 생성 | 서비스의 요청 횟수 제한 기능(IP 기준, 짧은 창)으로 막는다. IP를 우리 DB에 저장하지 않는다. Cloudflare의 무료 횟수 제한 기능 범위는 **미확인** |
| 초대 ID·열람 키 추측 | 128비트 무작위, 목록을 돌려주는 엔드포인트 없음, 틀린 키에는 같은 오류만 |
| 지도 긁어 가기 | 친구 목록은 열람 키가 있어야만 나옴, 초대 ID로는 주인 정보 한 줄만 |
| 욕설·광고 별명 | 길이 제한, 금칙어, 주소·전화번호 모양 차단, 주인의 개별 삭제 |
| 다른 사이트에서 함수 호출 | CORS를 우리 배포 주소 하나로 제한(브라우저 밖 호출은 못 막음 → 위 상한들로 막음) |
| 무료 한도 소진으로 본 사이트까지 멈춤 | 4장의 서비스 선택에서 다룸. 한도가 차도 **지도 기능만** 멈추고 일곱 방·책은 동작해야 한다 |
| 로봇 확인(CAPTCHA) | Cloudflare Turnstile 같은 무료 확인을 쓰면 외부 스크립트가 늘어 3장 예외가 하나 더 필요하다. **이번에는 넣지 않고**, 남용이 실제로 생기면 다시 제안한다 |

## 3. CLAUDE.md 개정 문안

### 3-0. 범위: 이 제품의 이 기능만 vs 공장 전체

| 안 | 내용 | 장점 | 단점 |
|---|---|---|---|
| **좁게(추천)** | 예외를 "strange-oracle 친구 궁합 지도"로 이름 붙여 한정. 다른 제품이 쓰려면 운영자가 새로 결정 | 개인정보 1순위(1장)와 가장 잘 맞음. 공장의 다른 빠른 제품들이 "서버 써도 된다"로 번지지 않음. 시험 기간을 거쳐 효과를 볼 수 있음 | 다음 제품에 같은 기능을 쓰면 개정을 또 해야 함 |
| 넓게 | "사용자 동의를 받은 결과 모음 기능"을 공장 공통 규칙으로 허용 | 다음 제품에 바로 재사용 | 아직 한 번도 운영해 보지 않은 서버 저장을 전 제품에 열어 둠. 제품마다 저장 칸·법률 검토가 달라 규칙이 느슨해지기 쉬움 |

- **추천: 좁게.** 다만 조건 문장은 일반적으로 써 두어, 나중에 넓힐 때 "적용 대상" 한 줄만 바꾸면 되게 한다. 기능이 반응을 얻으면(성공 기준은 15단계) 그때 넓히는 개정을 제안한다.
- 아래 문안은 **좁게** 안이다. 넓게 안을 고르면 "(strange-oracle 친구 궁합 지도에 한함)"을 "(운영자가 기획서에서 허용한 결과 모음 기능)"으로 바꾸고 적용 제품 목록을 docs/common.md에 둔다.
- 1장과의 관계: 새 예외는 모두 1장 아래에 있다. 문안에 "애매하면 보내지 않는다"를 넣어, 예외 해석이 갈릴 때는 개인정보 쪽이 이긴다는 것을 분명히 한다.

### 3-2. 3장 기술 규칙

**제안** (6장 끝에 추가)

>   - 삭제: 지도 주인은 지도 전체와 친구 한 명씩을, 친구는 참여할 때 받은 삭제 코드로 자기 기록을 언제든 지울 수 있다. 삭제는 즉시 반영한다.

>   - 지도 열람 키·삭제 코드(무작위 값, 입력값 아님)는 화면에 보여 주어 사용자가 직접 보관하게 한다. 열람 키는 이 기기의 localStorage에 둘 수 있고 "이 기기에서 지도 잊기" 버튼을 둔다. [질문 5에 따라 바뀜] 초대 ID만 주소(URL)에 넣을 수 있고, 열람 키·삭제 코드는 주소에 넣지 않는다.
>   - 분석 이벤트에는 지도 만들기·참여·삭제 같은 행동 이름만 보내고, 별명·아이콘·초대 ID·열람 키는 보내지 않는다.

### 3-4. 7장 수익화

## 4. 서버·DB 선택지와 추천

확인 날짜 2026-10-16. 무료 한도는 바뀔 수 있다.

| 항목 | **Cloudflare Workers + D1(또는 KV)** | Netlify Functions + Netlify Blobs | Supabase 무료 |
|---|---|---|---|
| 무료 한도 | Workers 요청 하루 100,000회, 요청당 CPU 10ms. D1: 읽기 하루 500만 행, 쓰기 하루 10만 행, 저장 5GB. KV: 읽기 하루 10만, 쓰기·삭제·목록 각 하루 1,000, 저장 1GB | 계정 전체가 **한 달 300 크레딧**을 나눠 씀(운영 배포 1회 15, 계산 GB-시간당 10, 대역폭 GB당 20, 요청 1만 회당 2). **Blobs의 크레딧 단가는 공개되지 않음(미확인)** | DB 500MB, 파일 1GB, 전송 5GB/월, Edge Function 월 50만 회, 활성 프로젝트 2개 |
| 한도를 넘으면 | 그 종류의 작업만 오류로 실패(하루 단위, UTC 0시 초기화). 무료 요금제에서는 과금 없음 | **계정의 모든 사이트가 멈춤**("Site not available"). 본 사이트(일곱 방·책)까지 같이 멈춘다 | 무료 요금제는 과금 없음. 대신 **1주 동안 활동이 없으면 프로젝트가 일시 정지** |
| 데이터 위치 | D1·KV 모두 국가 지정은 eu·fedramp(KV는 비공개 베타)뿐, 한국 지정 불가. 실제 저장 위치는 위치 힌트에 따름(아시아 지정 가능 여부 미확인) → **국외(미국 회사)** | Blobs 지역 선택: 싱가포르·시드니·프랑크푸르트·미국 동부 2곳. 기본 us-east-2. 한국 없음 → **국외** | 서울(ap-northeast-2) 지역이 있음. **무료 요금제에서 서울 선택 가능 여부 미확인**. 회사는 미국 → 국내 저장이어도 국외 이전 해당 여부 미확인 |
| 계정 작업(운영자) | Cloudflare 가입, Worker·D1 만들기, 배포 설정. 결제 수단 없이 무료 사용 가능 여부 **미확인** | 이미 쓰는 Netlify 계정 그대로(추가 가입 없음). 현재 Netlify 요금제가 무료인지 **미확인** | Supabase 가입, 프로젝트 생성, 표·접근 정책(RLS) 설정 |
| 비용이 생기는 조건 | 유료 요금제(Workers Paid)로 올릴 때만. 무료에서는 한도에서 멈춤 | 크레딧 자동 충전이나 유료 요금제를 켤 때 | Pro($25/월)로 올릴 때 |
| 만료(TTL) | KV는 키 만료 기본 지원. D1은 하루 한 번 정리 작업(Cron) 필요(무료 Cron 범위 미확인) | 기본 만료 없음(미확인) → 함수로 정리 | 정리 작업 필요(pg_cron 무료 사용 여부 미확인) |
| 남용·보안 | 함수만 공개, 저장소는 외부에 직접 노출되지 않음 | 함수만 공개 | 브라우저가 DB에 직접 붙는 구조가 기본이라, 접근 정책(RLS)을 잘못 쓰면 **목록 긁어 가기가 바로 됨**. Edge Function만 쓰면 피할 수 있으나 설정이 늘어남 |
| 우리 저장소와의 궁합 | 함수가 따로 배포됨(배포 2곳). 브라우저가 Worker 주소로 fetch → CORS 설정 필요 | 같은 저장소·같은 배포(netlify.toml, 지금 `book` 함수 옆에 하나 더) | 함수가 따로 배포됨 |

**추천: Cloudflare Workers + D1** (D1이 쓰기 한도가 KV보다 100배 커서 참여가 몰려도 여유. 만료는 하루 한 번 정리 작업, 무료 Cron이 안 되면 "열 때마다 지난 기록 지우기"로 대체)
- 가장 큰 이유: **한도가 차도 지도만 멈춘다.** Netlify 안은 남용 한 번으로 300 크레딧이 바닥나면 본 사이트까지 멈춘다. 운영 배포 한 번이 15 크레딧이라 배포만 20번 해도 한도다. 지도가 본 제품을 위험하게 만들면 안 된다.
- 무료 한도에서 멈추고 과금되지 않는다는 점이 문서에 적혀 있다.
- 대가: 계정이 하나 늘고, 데이터가 국외(미국 회사)에 있다 → 국외 이전 고지 필요 여부는 **미확인, 법률 확인 필요**.
- 차선: 운영자가 계정을 늘리고 싶지 않으면 Netlify. 이때는 Netlify 사용량 경고와 지도 함수 하루 호출 상한(함수 안에서 셈)을 반드시 둔다.
- Supabase는 서울 지역이 장점이지만 1주 무활동 정지와 RLS 실수 위험 때문에 3순위.

- (b) localStorage를 쓰지 않고, 사용자가 열람 코드를 직접 복사해 보관한다(이어가기 코드와 같은 방식). 잃으면 지도를 다시 볼 수 없음.

**법률 확인이 필요한 것 (미확인, 법률 확인 필요) — 결정 전 planner 기본값으로 문안을 썼다**
1. 국외 저장(Cloudflare·Netlify·Supabase 모두 해외 회사)에 대해 개인정보처리방침의 국외 이전 고지·동의가 필요한지, 필요하면 무엇을 적어야 하는지. 기본값: 동의 화면과 처리방침에 저장 국가·회사를 적는다.
2. 만 14세 미만 처리. 기본값: 브라우저에서 계산해 만 14세 미만은 만들기·참여를 막는다(법정대리인 동의를 받지 않음).
3. 별명·원형 코드가 개인정보에 해당하는지(아는 사람끼리라 별명만으로 식별 가능), 그에 따른 수집 동의 문구의 충분성.
4. 횟수 제한을 위해 서비스가 IP를 잠시 처리하는 것의 고지 범위.
