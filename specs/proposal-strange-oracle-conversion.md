# 제안서: 상품성 개선과 결제 전환 최적화 (운영자 작성, 2026-10-17 접수)

> 운영자가 "17단계가 끝난 뒤 작업할 개선 기획서"로 보낸 원문이다. 원문은 메인 세션 대화에 있고, 여기에는 요지와 메인 세션 검토를 적는다. planner는 17단계 QA 뒤 이 문서와 검토를 바탕으로 18단계 기획을 쓴다.

## 원문 요지
- 목적: 세계관·디자인은 유지하고, 첫 화면 이해도를 높이고, 무료/유료 경계를 분명히 하고, 3,900원 종합 리포트의 전환율을 높인다.
- 원칙: 기존 코드 분석 먼저, 동작하는 기능 삭제 금지, 구현 안 된 것을 된 것처럼 표시 금지, 실제 결제 설정 변경 금지, 확인 못 한 것은 성공으로 보고 금지.
- 흐름: 메인 → 콘셉트·무료/유료 안내 → 입력 → 방 탐험 → 방별 무료 결과 → 종합 미리보기 → 결제 화면 → 3,900원 → 전체 리포트 → 저장·복원·공유.
- 메인: "무엇인지·무엇이 특별한지·무료로 무엇·유료로 무엇"을 첫 화면에서. 체계 개수는 확인 뒤 확정. 소요 시간은 실측 전 확정 금지.
- 무료 결과: 체계 설명, 키워드 2~3개, 대표 해석 2~4문장, 핵심 특징, 다음 방 버튼. 유료 가치를 대체하지 않을 것.
- 유료 리포트: 체계별 상세·근거, 체계 간 공통점·차이, 성향·관계 상세, 선택한 관심사 심층, 최종 종합 결론, 책 형태.
- 결제 지점: 모든 방을 마친 뒤 종합 리포트 직전. 결제 직전 화면 = 제목·전체 목차·실제 결과 기반 샘플 페이지·무료/유료 차이·일회성·가격·버튼.
- 친구 궁합: 무료 성장 장치, 구매와 독립. 점수를 절대적 수치처럼 표현하지 않음.
- 개인정보·복원 점검 목록, QA 목록, 구현 순서(분석 → 개선 → 점검 → QA → 보고), 이벤트 설계(experience_started 등 11개), 완료 조건.

## 메인 세션 검토 (2026-10-17)

### 이미 된 것 (원문 원칙과 맞음)
- 방은 **일곱 개**로 확정(운영자 결정 83·91, Ⅰ 만신의 방). 원문의 "여섯" 문구 예시는 "일곱"으로 바꿔 쓴다.
- 모든 방 무료, 결제는 책(유료 장)에만. 결제 SDK는 버튼 뒤에만, 배포판은 pay.mode off(결정 94), 실제 결제 설정은 운영자 몫(G7).
- 친구 궁합 지도는 무료·구매와 독립(결정 84·103). 다만 원문의 **"팔각형"은 현재 오각형**(16단계, 꼭짓점 = 궁합 축 5개)이다. 바꾸려면 운영자 결정 필요.
- 개인정보: 입력값은 브라우저에서만, sessionStorage, 서버로는 결제·지도의 정해진 칸만(CLAUDE.md 6장). 이어가기 코드(SOG2)는 생일을 추정할 수 있다는 경고가 화면에 있다. 열람 코드(SOP)는 결제 1건 1코드, 공유 위험은 15단계에서 다룸.
- 원문 10장 QA 목록 대부분은 e2e로 이미 자동 시험 중(단위 151, e2e 6종).
- 이벤트: 지금은 so_visit·so_room_view·so_result·so_story·so_share·so_resume·so_book·so_pay·map_* (GA4, 행동·단계 이름만). 원문 11개 이벤트로 이름을 맞추는 것은 어렵지 않다. 단 `share_link_opened`·`shared_user_experience_started`는 공유 링크 출처를 구분해야 해서, URL에 추적 값을 넣지 않는 방식(6장)으로 설계해야 한다.

### 원문과 지금 구조가 부딪히는 곳 (운영자 결정 필요)
1. **무료 결과 분량.** 지금 방마다 무료 결과가 약 3,000~4,000자다(나의 이야기·공유 카드의 바탕). 원문은 "대표 해석 2~4문장"이다. 크게 줄이면 전환에는 유리할 수 있으나, 무료 체험의 만족·공유 화제·애드센스식 "충분한 콘텐츠" 원칙(7장 소개 글 300자는 별개)과 부딪히고, 기존 문구 수만 자를 유료로 옮기는 큰 작업이 된다. 권장: 무료 결과를 없애지 말고 "핵심 풀이까지 무료, 흐름·근거·관계 심화는 책으로" 경계를 다시 긋는 정도.
2. **결제 지점.** 지금은 첫 방을 마치면 책 목차가 열리고 7/7 전에도 살 수 있다(결정 59·77). 원문은 "모든 방을 마친 뒤". 원문대로 하면 결제 기회가 줄고, 지금대로면 원문 원칙과 어긋난다. 권장: 결제 버튼의 **주 노출**은 7/7 종합 미리보기에서, 7/7 전에는 목차만 보이고 결제는 작게.
3. **샘플 페이지.** "실제 결과 기반 샘플 페이지"는 유료 문장을 결제 전에 보내야 한다. CLAUDE.md 7장(유료 문구는 결제한 사람만)과 부딪힌다. 권장: 무료인 여는 글·닫는 글(data-book-free.js)과 「첫 줄」(17단계 firstLine)을 샘플로 쓰고, 유료 본문은 보내지 않는다.
4. **관심사 선택 심층 해석.** 지금 없는 기능이다(연애는 17단계 인연의 장으로 들어감). 진로·재물·고민을 더하려면 새 입력(관심사 선택)과 수만 자 문구가 필요하고, 재물은 8장(투자 권유 금지)과 가깝다. 권장: 18단계에서는 "연애(인연의 장)·일·관계" 정도의 기존 장 묶음을 관심사 순서로 다시 배열하는 수준부터.
5. **체계 간 공통점·차이 분석.** 지금 책의 원형 심층·나의 이야기가 일부 하지만 "해석이 갈리는 부분"을 명시적으로 다루는 장은 없다. 새 장 하나(약 1~2만 자, 원형·방 결과 조합으로 조립)가 필요하다. 원문의 유료 차별점 핵심이므로 18단계 1순위 후보.

### 원문 원칙과 CLAUDE.md의 관계
- 원문 14장 "Claude Code 작업 지시"는 CLAUDE.md 9장 흐름(planner 기획 → 검수 → 디자인 → 개발 → 문구 → 점검 → QA)으로 진행한다. 원문의 "1단계 기존 코드 분석·차이 보고"는 이 검토와 18단계 기획서의 첫 절이 맡는다.
- 메인 첫 화면에 가격을 보이는 것은 결제가 켜진 판(test·live)에서만이다. 배포판(off)에서는 가격·결제 말이 없어야 한다(결정 94, build-dist 가드).
