# 제안서: 첫 방 일부 공개 후 결제 / 카카오·네이버·구글 로그인 (2026-10-22, planner)

운영자 질문 두 가지에 대한 검토다. 운영자가 고르기 전 단계이며, 가격 9,900원(운영자 결정 131)만 바로 반영했다.

## 1. "처음부터 정보 입력 → 첫 방 일부만 공개 → 결제" 방식

### 결론: 지금은 하지 않는 것을 권한다 (대신 아래 B안)
| 근거 | 내용 |
|---|---|
| 데이터가 0이다 | 결제를 켠 지 하루다. 지금 구조(일곱 방 무료 + 1/7부터 결제 버튼, 결정 128)의 전환율을 아직 한 번도 재지 않았다. 재지 않은 상태에서 구조를 바꾸면 무엇이 좋아졌는지 알 수 없다. |
| 처음 보는 브랜드 | 광고로 처음 들어온 사람에게 결과를 거의 보여 주지 않고 9,900원을 묻는 방식(하드 페이월)은 신뢰가 쌓인 서비스에서 통한다. 국내 운세 서비스도 대개 기본 풀이는 무료, 깊은 풀이는 유료다(미확인: 업체별 실측 아님, 일반적 관행). |
| 공유가 유입이다 | 지금 유입의 엔진은 방마다 나오는 공유 카드와 "3/7 링크 복사"다. 첫 방에서 막으면 공유할 결과가 없어 광고비 없이 들어오는 사람이 줄어든다. |
| 규칙(7장)과 개발량 | 방 결과 문구는 지금 공개 파일(data-*.js, 약 690KB)에 있다. "일부만 공개"를 진짜로 하려면 유료가 되는 부분을 공개 파일에서 빼서 서버(함수 book)로 옮겨야 한다(유료 문구를 정적 파일에 두면 7장 위반이고, 누구나 개발자 도구로 볼 수 있다). 일곱 방 계산·화면·공유 카드·시험을 거의 다시 짜는 일이라 몇 주짜리다. |
| 광고 심사 | 나중에 애드센스를 다시 붙일 때 무료 콘텐츠가 충분해야 심사에 유리하다(7장 소개 글 규칙). |

### B안 (권장): 지금 구조를 2주 재고, 그다음 한 단계씩
1. 지금 그대로 2주 측정(GA4 `so_pay` view·start·done, from별). 결정 128로 이미 첫 방부터 결제 버튼이 있다.
2. 전환이 낮으면 **만신의 방 결과 화면 안**에 "이 방의 장 전체(약 5,800자) 무료 열람 → 끝에서 나머지 책 9,900원" 흐름을 더 앞에 둔다(만신 장은 이미 무료라 개발량 작음).
3. 그래도 낮으면 그때 "방 2~7 결과 일부 공개" 같은 강한 잠금을 A/B로 시험한다(그때는 문구 서버 이전 기획서를 따로 쓴다).

## 2. 카카오·네이버·구글 로그인

### 왜 쓰나
- 지금은 결제 뒤 받은 **열람 코드(SOP-…)**로 다른 기기에서 책을 다시 연다. 코드를 잃으면 문의로 다시 발급한다(약관 5조).
- 로그인을 붙이면 "로그인하면 산 책이 다시 열림"이 되어 코드 분실 문의가 줄고, 재방문(2028년판 등)을 묶기 쉽다.

### 걸리는 것
| 항목 | 내용 |
|---|---|
| CLAUDE.md | 3장(서버는 결제 확인·유료 전달 최소 함수만, DB 없음)·6장(입력값 외 개인정보) 개정이 필요하다. 간편 로그인은 운영자 결정 37로 "개정 전까지 보류" 상태다. |
| 개인정보 | 로그인하면 회원 식별자(카카오 회원번호 등)를 받는다. 개인정보처리방침에 수집 항목·목적·보관 기간·파기, 만 14세 미만 처리, 국외 이전(Netlify) 고지가 늘어난다. |
| 저장 | 회원 식별자 ↔ 열람 코드 해시 연결을 Netlify Blobs에 둔다(이름·이메일·전화는 받지 않는 범위로 최소화). |
| 제공자 등록 | 카카오 디벨로퍼스 앱 등록·도메인/리다이렉트 URI, 네이버 로그인 API 검수(서비스 URL·화면 캡처 제출), 구글 OAuth 동의 화면(앱 이름·개인정보처리방침 URL). 모두 운영자 계정 작업이다(10장). 비즈 앱 전환·추가 동의 항목은 미확인. |
| 개발 | OAuth 콜백 함수 1개 + 세션(서명 쿠키 — 6장 쿠키 금지는 "입력값"에 관한 것이나 해석 확인 필요) + 화면(로그인 버튼·내 책 열기) + 시험. 제공자 하나당 약 1~2일, 셋이면 약 1주(추정). |

### 권장
- **지금은 보류, 하게 되면 카카오 하나부터.** 국내 사용자 대부분이 카카오 계정이 있고, 공유도 카카오톡이 주력이다. 네이버·구글은 이용자 요청이 생기면 더한다.
- 받는 값은 **회원번호만**(닉네임·이메일·전화 동의 항목은 요청하지 않음). 서버에는 회원번호의 HMAC 해시와 열람 코드 해시만 둔다.
- 순서: ① 운영자가 CLAUDE.md 3·6장 예외 문구 결정 → ② 기획서(20+단계) → ③ 기획 검수 → 개발 → 개인정보처리방침 → QA.
