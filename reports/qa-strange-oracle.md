## 4. 조건 (운영 배포 전) — 시험 주소의 심층상담 무제한
- 무엇: `netlify/lib/talk.js` testEnv · `auth.js` respond — 배포 종류가 branch-deploy(작업 브랜치 시험 주소)면 카카오 로그인한 누구나 별가루 없이 심층상담을 계속 쓸 수 있다(10분에 IP당 60회, 함수 인스턴스마다 따로 셈).
- 왜 문제: 시험 주소도 운영과 **같은 저장소(Netlify Blobs, 사이트 단위)**와 같은 API 키를 쓴다. 그래서 시험 주소에서 쓴 비용이 운영의 월 상한(`budget/<월>`)을 함께 깎는다. 운영 배포 뒤 시험 주소가 알려지면 무료로 상한까지 쓸 수 있고, 상한에 닿으면 그달 **운영의 유료 심층상담도 닫힌다**. 돈이 상한 이상 나가지는 않는다(월 상한은 시험 주소에도 그대로).
- 고치는 방법(하나 고르기):
  1. 운영 배포 직전에 개발자가 시험 무제한을 끈다(코드 몇 줄) — 추천.
  2. Netlify에서 작업 브랜치 배포를 끄거나 비밀번호로 막는다(운영자, Netlify 화면).
  3. 시험 무제한을 `TALK_EVAL_KEY` 머리가 있을 때만으로 좁힌다.
- 같은 이유로, 시험 주소에서 한 카카오 로그인·별가루 충전·책 열기는 운영 계정 기록에 그대로 남는다(이전부터 그랬음, 기록용).

## 5. 시험으로 확인하지 못한 것 (운영자가 실제로)
- **카카오 로그인 복귀 길 변경(auth.html)**: 시험 주소에서 처음 화면·별가루·오늘의 신탁에서 로그인 → 원래 페이지로 돌아오고 별가루가 보이는지, 입구에서 로그인 → 입구로 돌아오는지. (모의 서버로만 확인. 카카오에 등록한 리다이렉트 주소는 그대로)
- 실제 휴대폰에서 버벅임 체감(측정은 화면 없는 브라우저, CPU 4배 느리게).
- 이전 보고서 4장의 것(실제 페이앱 결제·환불, 실제 카카오 로그인, 심층상담 실모델 금지 주제 시험)은 그대로 미확인.

## 6. 경미한 개선(배포를 막지 않음)
- 광고 유입 첫 방문은 소개 글이 있는 입구를 건너뛰고 만신의 방 입력으로 바로 간다. 소개 글은 입구에 그대로 있어 광고 심사(7장 300자)에는 문제 없음 — 기록만.
- 심층상담 10분 횟수 제한은 함수 인스턴스 기억 안에서만 센다(동시 접속이 많으면 실제 한도가 더 느슨함). 월 비용 상한이 최종 안전장치 — 이전부터 그랬음.
