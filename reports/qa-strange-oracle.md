## 권장 사항
1. **"반드시" 표현**: data-runes.js·data-stars.js의 넷째 장(다음) 조언에 "폭풍은 반드시 지나갑니다", "결실은 반드시 옵니다" 등 격려성 문장에 "반드시"가 여러 번 쓰였다. CLAUDE.md 8장의 "반드시 ~한다처럼 단정하지 않는다" 규정은 문면상 "나이·시기별 흐름(예지형)" 콘텐츠에 걸려 있고, 이번 1단계 룬·나크샤트라 콘텐츠는 나이대 예지가 아니라 일반적 격려 문장이라 위반으로 보지는 않았다. 다만 6단계 유료 리포트(나이·시기별 흐름)를 쓸 때는 이 표현 습관을 그대로 가져가지 않도록 copywriter가 유의할 것을 권한다.
2. **R5 단서**: 라히리 아야남샤 자체 구현분의 검증 기준(Swiss Ephemeris 대조)이 CLAUDE.md 3장이 말하는 "교과서 예제 값 대조"의 정신에 부합하는지는 판단이 갈릴 수 있는 부분이라, 운영자가 tests.md의 해당 근거(정의점 출처, IAU 2006 세차식)를 한 번 훑어보길 권한다.
3. **share-buttons.js 미존재**: docs/common.md 기준 아직 프로젝트 전체에 share-buttons.js가 없다(strange-oracle도 share-card.js의 자체 share() 함수만 사용). 위반은 아니지만(spec에 이 부품이 필요하다는 언급 없음), 다음 제품에서 카카오톡 공유 등을 붙일 때 공통화가 필요하면 참고할 것.
4. **UI 점검 잔여 확인 항목**: design.md UI 점검이 "확인 안 됨"으로 남긴 것 중 480px과 공유 카드 안전영역은 이번 QA에서 직접 확인해 해소했다(위 R1·P8 참조). "나의 이야기 방 0개 화면"은 이번 QA에서 별도로 스크린샷 촬영은 하지 않았음(코드상 `.is-empty` 분기와 `공유 버튼 숨김` 로직은 app.js에서 확인했으나 렌더링 결과 캡처는 안 함) — 운영자가 실제 기기로 한 번 보는 것을 권장.

## 확인하지 못한 것과 이유
- "나의 이야기" 방 0개(첫 방문) 화면의 실제 렌더링 스크린샷 — 코드 로직만 확인, 시간 관계상 캡처는 생략. 배포를 막을 사안은 아니라고 판단했으나 운영자 확인을 권장.
- M2(태양 겉appent 황경)의 Meeus 책 인쇄값 원문 대조 — tests.md에도 "미확인"으로 이미 명시돼 있고, 이번 QA에서 새로 확인할 방법이 없어 그대로 남김.
- 실제 기기(터치스크린, 모바일 브라우저별 공유 시트)에서의 동작 — 헤드리스 Edge와 PC 에뮬레이션으로만 확인했다. navigator.share가 없는 환경(헤드리스)에서는 항상 "다운로드" 경로로 빠지므로, 실기기의 공유 시트 자체는 못 봤다.
- 검색 키워드 실제 검색량, 광고 심사 통과 여부 등은 QA 항목이 아니라 원래도 확인 대상이 아님.

## 운영자가 브라우저로 직접 확인할 것

## 수정 필요 항목 상세
1. **(경미, 배포 차단 아님) `tools/strange-oracle/e2e-paid.js:154`의 motion 모드 레이스**: `await sleep(300)` 뒤 바로 `hidden("[data-js=hub-report]")`를 검사하는데, `app.js`의 `go()`가 `!reduceMotion`일 때 화면 전환을 `setTimeout(reveal, 320)`로 320ms 지연시킨다(app.js:283). 300ms < 320ms라 motion 모드에서 간헐적으로 FAIL(3회 중 2회 재현, "허브: 내 리포트 다시 보기 보임"). 실제 제품 동작은 정상(사용자는 실제 화면 전환이 끝난 뒤 버튼을 보게 됨) — 테스트 하니스의 고정 sleep 값이 짧은 것뿐이다. developer가 sleep을 400ms 이상으로 늘리면 해결됨.
2. **(경미, 정보성) D-11 체크가 하드코딩된 true**: `e2e-paid.js:129`의 `check("D-11 분량...", true, ...)`는 실제 ±15% 조건을 판정하지 않고 항상 통과로 표시한다. 이번 QA에서는 수치(8,600→8,109, -5.7%)를 직접 계산해 기준 내임을 확인했지만, 자동 회귀에서는 이 값이 15%를 넘어도 테스트가 알려주지 않는다. developer가 실제 `Math.abs(expectTotal-metaN)/expectTotal <= 0.15` 조건으로 바꾸는 것을 권장.

### 권장 사항 (배포를 막지 않음)
1. `PAY_DEBUG_FIELDS=1`이면 칸 이름 로그가 **인증 전에** 찍힌다(pay.js:159). 값은 없지만, 켜 둔 동안 위조 요청으로 로그를 채울 수 있다. G7 ⑦은 칸 이름이 달라 인증이 실패하는 경우도 보아야 하므로 지금 위치도 이유가 있다. 운영자는 실결제 시험 직후 바로 끈다.
2. off 배포판 `dist/public/.../index.html` 원본(주석 제외)에 결제 마크업이 들어 있다: "결제" 36회, "3,900" 3회, "판매자 ◯◯" 등 ◯◯ 6회. 화면 DOM은 JS가 지워 0개이므로(J2) 합격 기준 1은 만족한다. 다만 소스 보기·검색 로봇에는 보인다. live 가드 ⑦은 index.html 정적 ◯◯를 보지 않는다(data-t가 data.js 값으로 덮으므로 화면에는 문제가 없다). off일 때 build-dist가 결제 구간을 빼면 필수 1과 함께 정리된다.
3. 횟수 제한 Map 정리(pay.js:80, book.js:71)는 항목이 5,000개를 넘으면 요청마다 전체를 돈다. 지금 규모에서는 문제가 없다.
4. **e2e-pay I8 글꼴 CORS 오류**
   - 이번 실행(62/0)에서는 재현되지 않았다.
   - jsdelivr는 글꼴의 200 응답과 404 응답 모두에 `access-control-allow-origin: *`를 준다(curl로 확인). 그래서 우리 설정이나 SRI 문제는 아니다.
   - 원인은 **추정**이다. 결제창 이동·팝업 닫기로 글꼴 요청이 중간에 끊기거나 일시적인 네트워크·CDN 오류로 응답이 실패하면, 크롬이 이를 "blocked by CORS policy"로 기록하는 경우로 보인다(미확인).
   - 글꼴은 대체 글꼴로 표시되고 기능에는 영향이 없다. **배포를 막지 않는다.**
   - 시험을 안정시키는 방법: I8 거르개에 글꼴 주소(`cdn.jsdelivr.net/npm/@fontsource`)의 CORS 줄을 넣는다. 또는 결제 버튼을 누르기 전에 `document.fonts.ready`를 기다린다.
